# Автопроверка инструкций и памяти DASH

**Статус:** proposed. Это синтаксический/структурный gate, не подмена предметного ревью.

## Предсказуемые проверки

1. Сверить все пути приватного реестра `EDITORIAL_DECISIONS_250.csv` с pinned source manifest. Ровно 250/250 исходных путей, все Git blob SHA и SHA-256 равны.
2. Из всех активных root/scoped MD и новых contract-файлов проверить локальные ссылки; не требовать, чтобы упоминаемые в исторических цитатах `C:/`-пути существовали.
3. Проверить, что `CLAUDE.md` импортирует единственный `@AGENTS.md`; у Copilot одно `copilot-instructions.md`, а `.claude/rules` содержат корректную область действия.
4. Проверить наличие `name`, `description` в каждом `SKILL.md`, уникальность имён, отсутствие правил, запрещающих работу при отсутствии внешнего vault.
5. Сравнить root/scoped инструкции на дубли и конфликты; намеренные safety carve-outs принимаются только после проверки проекта.
6. Проверить на точном HEAD `.github/ci/deploy_scope.py`: `docs/**` и разрешённые корневые MD не должны запускать runtime; новые `.claude/**` и `.agents/**` требуют отдельной подготовки и подтверждения.
7. Провести поведенческие тесты двух агентов: фильтр УО→школа→период→бюджет, `AD=нет`, `Q=null`, `173/1 != 173/2`, неполный Word publish, stale weekly baseline, отказ записи/формулы.
8. Перед публикацией `STATUS` заново проверить Git PR `state`, `draft`, `merged`, base/head SHA и фактический merge. Формулировка «PR не создавался» или «внедрено» без fresh readback считается ошибкой. Срез статуса содержит `asOf` и событие его инвалидирования.
9. Negative baseline test: при отказе любого из восьми masters, отсутствующем СВОД, устаревшем watermark, дубле webhook или write failure последний complete baseline/receipt и предыдущий release остаются теми же; `last_attempt` показывает отказ, `last_verified` сохраняет свой timestamp. Без `sourceCoverage=100%` новый `PASS` запрещён. Не считать проверку проведённой, пока нет выполняемого теста, trace и результата exact-head.
10. Контроль сохранённых исключений при сокращении инструкций: разрешены **только** верифицированные обезличенные `packages/core/src/report/__fixtures__/week-*.json`, не приватные полные отчёты. В cross-agent тесте агент должен отличить ограниченное разрешение от общего запрета секретов.
11. После любой редакторской перестановки проверять обратные ссылки и статус первоначального тезиса в реестре, границу `current`/`historical`, отсутствие конфликтующих вариантов в always-on инструкциях. Это структурный тест, не 250 независимых экспертных заключений.

## Исполняемый локальный страж

`python docs/engineering/verify_agent_docs.py --json` — проверка минимальных инвариантов инструкций без сети и доступа к production. Для исходного корпуса добавь `--source-zip /путь/к/Dash_all_250_MD_2026-10-22.zip`: сверяет **все** 250 SHA-256, Git blob SHA-1 и размеры по MANIFEST.json. Если код отсутствует в documentation-only пакете, проверка кода явно помечается `SKIPPED`; не выдавай такой прогон за проверку runtime. Любой fail возвращает ненулевой exit.

## Какие проверки выполнялись локально

`python scripts/verify_pack.py` проверяет 250 хешей, source cards, маршрутизацию и структуру пакета. Верифицирует целостность текста, **не** прохождение всех смысловых правил. Протокол и результаты — в приватном архиве. Production/Sheets/UI нуждаются в отдельных испытаниях.
