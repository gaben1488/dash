## Разбор каждого замечания и критерий приёмки

### DASH-001 — Запись по позиции строки без сверки объекта

**Вердикт:** Код подтверждён (P1). **Основание:** [rows.ts:73-79](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/routes/rows.ts#L73-L79) · [rows.ts:277-405](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/routes/rows.ts#L277-L405) · [google-sheets.ts:899-929](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/services/google-sheets.ts#L899-L929).

PUT/POST принимают dept+rowIndex; rowWriteError проверяет номер только по границам кэша, writeCellValue пишет в тот же A1-адрес. Перед записью нет повторного чтения или сравнения идентичности объекта.

**Ограничение доказательства:** Неверная адресация возникает при внешнем перемещении/сортировке между чтением и записью. Реальный конфликт на боевой книге этим аудитом не воспроизводился.

**Следующий безопасный шаг:** Перед каждой правкой сравнивать ожидаемую идентичность и исходные значения с текущей строкой; при несовпадении 409 и сохранение черновика.

**Проверка исправления:** Открыть закупку в тестовой книге, переместить её, затем сохранить старый индекс: ни одна чужая ячейка не меняется.

**Вердикт:** Код подтверждён (P1). **Основание:** [column-map.ts:102-105](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/shared/src/column-map.ts#L102-L105) · [rows.ts:64-79](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/routes/rows.ts#L64-L79) · [rows-write-bounds.test.ts:33-49](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/rows-write-bounds.test.ts#L33-L49).

**Ограничение доказательства:** Путь записи требует полномочия на API и права сервисного аккаунта в источнике. Тест реального Google API здесь не запускался.

**Следующий безопасный шаг:** Минимальная строка данных = DEPT_HEADER_ROWS+1; отдельно отклонять итоги/служебные строки и проверить guard в PUT и POST.

**Проверка исправления:** Обе ручки блокируют 1,2,3, ИТОГО и за пределами; принимают существующую рабочую строку 4.

### DASH-013 — Поштучная запись без полного следа изменения и атомарности

**Вердикт:** Код подтверждён (P1). **Основание:** [rows.ts:369-404](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/routes/rows.ts#L369-L404) · [rows.ts:437-625](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/routes/rows.ts#L437-L625) · [DataBrowser.tsx:574-590](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/web/src/pages/DataBrowser.tsx#L574-L590).

**Ограничение доказательства:** Прошлая общая формулировка 'частичные отказы скрыты' неверна: обработка 207 уже существует и покрыта rows-batch-write.test.ts. Проблема — атомарность, повтор и полнота аудита.

**Проверка исправления:** Симулировать запись первой и отказ второй ячейки: UI правильно показывает обе судьбы; повтор не теряет след и не переписывает чужие изменения.

### DASH-014 — Ввод дат проверяет форму, но не календарь

**Проверка исправления:** Отклонять 31.02.2026, 2026-13-99, 2026-01-14garbage; принимать 29.02.2024.

### DASH-015 — Локализованные корректные денежные ячейки дают ложные ошибки

**Вердикт:** Снято как production-баг (—). **Основание:** [rule-book.ts:37-46](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/shared/src/rule-book.ts#L37-L46) · [source-validation.ts:113-135](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/services/source-validation.ts#L113-L135) · [google-sheets.ts:279-299](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/packages/server/src/services/google-sheets.ts#L279-L299).

**Следующий безопасный шаг:** Не менять валидаторы вслепую; при наличии реального спорного случая проверить userEnteredValue/effectiveValue и контракт текстовых сумм.

**Проверка исправления:** При появлении подтверждённой проблемной ячейки добавить её минимальный fixture, тогда решать политику текста.

### DASH-017 — HTTP-режим возможно запустить без обязательного TLS-гейта

**Вердикт:** Риск конфигурации (P2). **Основание:** [docker-compose.yml:18-25](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/deploy/docker-compose.yml#L18-L25) · [.env.production.example:24-33](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/deploy/.env.production.example#L24-L33) · [Caddyfile:1-14](https://github.com/gaben1488/dash/blob/2461209c8d0172c4acf94f5606452c589cd4f510/deploy/Caddyfile#L1-L14).

## Проверочные свидетели и ограничения

1. Исполняемый результат реального `row_numbering`: [номер 173 / 173/1 / 173/2](https://github.com/gaben1488/dash/blob/a0c654190dad2c4edc0de00cbf9fbe443c16339f/docs/superpowers/audits/2026-10-10-dash-foundation/evidence/numbering-reproduction.json). Один модуль сообщает повтор, `sequence-integrity` — нет. Это доказательство на **том же main SHA**, а не новое доказательство сегодняшней production-таблицы.
2. Для денежных и календарных примеров отдельно исполнены **сами JavaScript-выражения из проверенного исходника** на Node 22: `parseFloat('12abc') === 12`, `parseFloat('1.2.3') === 1.2`, `parseFloat('1e309') === Infinity`; ISO regex принимает `2026-13-99` и `2026-01-14garbage`. Это **expression-level**, не end-to-end Google API.
3. `rows-write-bounds.test.ts` проверяет верхнюю границу, **но сам документирует ошибочную нижнюю 2** при шапке в три строки; зелёный тест не опровергает DASH-002.
4. У пакетной записи **реализованы** `207`, `ok:false`, `results[]`, а в DataBrowser обработаны failures. Не дублировать старый диагноз «клиент ничего не знает».
5. ШДЮ читается отдельно в `snapshot.shdyuData`. В реальном `pipelineInput.sheetRows` в штатном пути его нет: поэтому старое утверждение про `scope='both'` на ШДЮ не следует из production-вызова.
6. `getSheetData` использует `UNFORMATTED_VALUE`; корректные числовые ячейки Google поступают как числа, а не русские форматированные денежные строки. Без конкретного текстового source-case DASH-015 не активный баг.
7. Связка тестов: существующий [успешный CI](https://github.com/gaben1488/dash/actions/runs/37916827475) на Node 22 и [протокол локальных сбоев](https://github.com/gaben1488/dash/blob/a0c654190dad2c4edc0de00cbf9fbe443c16339f/docs/superpowers/audits/2026-10-10-dash-foundation/evidence/verification.json) (Node 24) — это противоречие среды **без установленной первопричины**. Здесь не запускали новый полный `pnpm -r test`, Python или Docker.
8. В защищённом деплое есть Caddy Basic Auth, токен на сервере и отдельный режим `AEMR_PUBLIC_READONLY`, который запрещает запись. **Не утверждать bypass**. Отдельного персонального доступа нет.

## Очередность без переписывания продукта

1. **Контур безопасной записи:** DASH-002, DASH-001, DASH-003, DASH-013, DASH-004. Regression-first на обоих HTTP-путях (одиночном и пакетном) + UI. Сначала запрет порчи данных; затем эргономика.
2. **Достоверность сигналов:** DASH-007 и DASH-010, затем DASH-008 и DASH-009. Параллельные схемы идентификаторов и номера колонок следует исправлять один раз в каноническом парсере/предикате.
3. **Правдивые статусы:** DASH-012, DASH-014; разделить «нет ошибок» и «проверка не выполнялась».
4. **Защита официального действия:** DASH-006, с учётом существующего read-only и без добавления фиктивного этапа согласования.
5. **Проверки условий:** сначала подтверждать сценарии DASH-005/016/017. Не перекладывать их в утверждённые баги без доказательства.
6. **Не делать лишнего:** не заводить новый MongoDB/Postgres ради перечисленного, не переписывать UI из-за размера файлов (DASH-018), не чинить месячный ШДЮ вслепую (DASH-011), не нормализовать корректные суммы без источника (DASH-015).

Решение для внедрения: отдельные небольшие PR с тестом до исправления, root-cause scope и зелёными гейтами `pnpm -r tsc --noEmit && pnpm -r test`. **Этот PR — документационный; ошибок в production он не исправляет.**
