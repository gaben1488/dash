## Архитектурная модель для исправления, без лишних сущностей

Действующая граница `Google Sheets → shared/core → server snapshot/API → web` правильна как разделение ответственности, но код должен соблюдать **единый факт** на каждом шве: идентичность строки, календарный день, способ закупки, ГРБС, валидность числа, полнота чтения и успешность сохранения.

Минимальные обязательные гейты:
- **Чтение:** источник, версия/момент, schema fingerprint, покрытие значений и формул, частичные ошибки. Обработка неверного или незнакомого листа не превращается в «замечаний нет».
- **Расчёт:** одинаковый периметр строк, нормализованные методы, тесты числителя/знаменателя, независимая сверка; `неизвестно` ≠ 0.
- **Запись:** ожидаемая личность объекта + ревизия, preflight, защита формульных и служебных ячеек, подтверждение changed-cells, журнал в одной допустимой транзакционной границе, явный частичный статус там, где атомарность между SQLite и Google Sheets недостижима.
- **Экран:** видимые причины неполноты, сохранение черновика при обновлении, доступные исходные строки для проверки числа, неизменность основных HTML/route/тем оформления без отдельного принятия.
- **Релиз:** одна версия данных, проверки сохранности исторических фактов и Word/экран parity, last-known-good и rollback. Ни одна заглушка не считается полноценной реализацией.

Рекомендуемый порядок приоритетов: безопасность записи + сохранность черновиков, затем точность KPI и подведов, далее корректность существующих правил/метрик, затем интерфейс и техническое упрощение. Не выбирать MongoDB по факту неодинакового текста ГРБС: сначала доказать конкретные ограничения актуального хранения и назначение полей.

## Что пока не может считаться завершённым полным аудитом

В рамках этого повторного прохода **проверены целевые пути и фактические восемь книг**, прочитаны девять исторических регистров. Не выполнена независимая динамическая проверка всех 1 576 файлов, всех живых агрегатов, экспортов, сценариев безопасности и визуальных состояний. Девять регистров нельзя механически объявить закрытыми, потому что содержащиеся в них 190 статусов относятся к августу. Новые баги можно закрывать только отдельным воспроизведением и CI, а не правкой Markdown. Этот документ нужен именно чтобы сегодняшняя версия долга не была ошибочно выдана за стопроцентно принятую.
