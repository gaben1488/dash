## 1. Правило года в коде

Правило года живёт в одном месте — `CalcEngine.compute`, и с 08.08 оно строгое по
умолчанию.

`packages/core/src/pipeline/calc-engine.ts:624-647`:

```ts
const rowYear = num(row[COL.PLAN_YEAR]);
const yearPolicy = opts?.emptyYearPolicy ?? (opts?.strictYear ? 'strict' : 'bucket');
const multiYear = opts?.years && opts.years.length > 0;
if (multiYear || targetYear) {
  if (rowYear > 0) {
    const inScope = multiYear ? opts!.years!.includes(rowYear) : rowYear === targetYear;
    if (!inScope) continue;
  } else if (yearPolicy === 'strict') {
    continue;
  } else if (yearPolicy === 'bucket') {
    // в срез не пускаем (лист её тоже не видит), но считаем отдельной корзиной
    for (const m of this.metrics) { … this.accumulate(result.noYear, …); }
    continue;
  }
  // 'lenient' — легаси: строка без года проходит в любой срез
}
```

Что здесь важно установить дословно:

- **Дефолт — `'bucket'`, а не `'lenient'`.** Строка с пустым P **не входит** в
  годовой срез. Прежний дефолт «пустой год проходит в любой год» (`lenient`) в
  коде остался только как явно запрашиваемый режим; ни один боевой вызов его не
  просит.
- **Фолбэка «взять год из даты N» нет.** Год читается ровно из P
  (`COL.PLAN_YEAR = 15`, `packages/shared/src/column-map.ts:35`). Ни N, ни S (год
  факта) в качестве замены не используются нигде в движке.
- Строка с пустым P не исчезает молча: она уходит в `result.noYear` — адресуемый
  остаток, который читается через `noYearRemainderOf`
  (`calc-engine.ts:956-968`).

Боевые вызовы, которые формируют числа продукта:

| Вызов | Адрес | Параметры |
|---|---|---|
| Пайплайн снимка (Пульт, дельты, сверка) | `packages/core/src/pipeline/orchestrator.ts:585` | `engine.compute(rows, standardRowFilter, 3, input.targetYear)` — политика по умолчанию `'bucket'` |
| Еженедельный отчёт | `packages/core/src/report/build-report.ts:576` | `ENGINE.compute(fundedRows, standardRowFilter, 0, year, { asOfDay })` |

Годовой итог собирается **суммой четырёх плановых кварталов**, а не из
негруппированного `total` — `packages/core/src/pipeline/calc-engine-adapter.ts:164-189`:

```ts
/** Год = сумма четырёх плановых кварталов (правило листа, см. док выше). */
const overQuarters = (pick: (q: QuarterMetrics) => number): number =>
  quarters.reduce((s, q) => s + pick(q), 0);
```

Следствие: строка с заполненным P, но пустым O в годовой итог не попадает — ровно
как на листе. Факт без планового квартала держится отдельным полем `_orphan`
(`calc-engine-adapter.ts:162`) и слагаемым года не является.

Гейт факта — `packages/shared/src/fact-date.ts:19-21`: заглушки `Х/X/-/—/–/н/д/нет/не
определена` и пустая ячейка означают «факта нет». Лист требует того же тремя
условиями `Q<>"Х"; Q<>"X"; Q<>""`.

Способ — тотальное разбиение `packages/core/src/pipeline/calc-engine.ts:279-282`:
не ЕП значит конкурентная, третьей группы нет. Лист определяет конкурентные тем же
отрицанием `L<>"ЕП"`.

## 2. Правило листа СВОД ТД-ПМ

Формулы взяты из дампа книги СВОД (лист «СВОД ТД-ПМ»). Канонический вид плановой
суммы, ячейка `H7`:

```
=H161+SUMIFS('УО'!H4:H3501; 'УО'!L4:L3501;"<>ЕП"; 'УО'!O4:O3501;1;
             'УО'!P4:P3501;2025; 'УО'!F4:F3501;B$1)
```

и счёт факта, ячейка `E7`:

```
=E161+COUNTIFS('УО'!L4:L3501;"<>ЕП"; 'УО'!O4:O3501;B7; 'УО'!P4:P3501;C7;
               'УО'!Q4:Q3501;"<>Х"; 'УО'!Q4:Q3501;"<>X"; 'УО'!Q4:Q3501;"<>";
               'УО'!F4:F3501;B$1)
```

Периметр листа, разложенный по условиям: квартал `O` равен конкретному числу, год
`P` равен конкретному году, вид деятельности `F` совпадает с переключателем `B1`
(его значение — `*`, то есть «любой текст», подпись в `A2`: «* = ТД + ПМ»), способ
`L` либо равен «ЕП», либо не равен ему. Год листа — сумма периодных строк
(`D13=SUM(D7:D12)`, `D14=SUM(D9:D12)` для 2026).

То есть **лист и движок описывают один и тот же периметр разными словами**.

## 4. Спорные множества

Три множества, из-за которых расхождение теоретически могло бы возникнуть. Все
измерены на строках книг ГРБС в периметре счётного фильтра продукта.

**(а) Способ заполнен, K > 0, N и P пусты.** Одна строка на весь район.

| ГРБС | строк | Σ K, тыс. руб. | адрес |
|---|---:|---:|---|
| УАГЗО | 1 | 60 000,00 | строка 12 листа «ВСЕ», «Демонтажные работы», способ ЭА |
| остальные семь | 0 | 0,00 | — |

Строка не входит ни в наш годовой срез, ни в формулы листа: без P её некуда
адресовать. У нас она названа — лежит в корзине `noYear` и в отчёте выходит
секцией «без подтверждённого финансирования» (`build-report.ts:264-269`).

**(б) O пуст при заполненном P.** **Ноль строк** во всех восьми книгах. Именно
это множество и было бы источником «наш год шире листового», потому что
негруппированный `total` его бы подхватил, а сумма кварталов — нет. Его просто
нет в данных; конструкция «год = Σ кварталов» здесь работает вхолостую, но
работает правильно.

**(в) ЕП с заглушкой Q и фактом > 0.** 46 строк, Σ факта **5 307,21 тыс. руб.**;
все 46 — внутри периметра 2026 (O = 1..4, P = 2026), то есть в плане они
посчитаны обеими сторонами, а в факте — ни одной.

| ГРБС | строк | Σ факта, тыс. руб. | примеры (строка листа «ВСЕ»; факт) |
|---|---:|---:|---|
| УКСиМП | 40 | 5 078,49 | 4 → 800,00; 6 → 367,60; 13 → 311,25; 17 → 170,00; 19 → 144,29 |
| УДТХ | 3 | 218,02 | 55 → 179,84; 61 → 19,32; 64 → 18,86 |
| УФБП | 3 | 10,69 | 13 → 3,40; 25 → 4,20; 26 → 3,10 |
| остальные пять | 0 | 0,00 | — |

Это не расхождение счёта, а дефект первички: деньги в V/W/X проставлены, дата
контракта в Q — нет. Сами книги ГРБС этот случай подсвечивают условным
форматированием (`=AND(REGEXMATCH(UPPER($Q4);"^[ХX]$"); OR($V4>0;$W4>0;$X4>0))` —
серая заливка, жирный шрифт), то есть владелец правила о нём знает.

**Остаток «без года плана» целиком** (шире, чем (а) — без условия K > 0 и без
условия по способу): 554 строки, Σ K = **294 592,43 тыс. руб.** по району, из них
УО — 536 строк на 180 375,46. Существенная деталь: **у всех 554 строк пуст ещё и
квартал O**, а в N стоит заглушка «Х»/«х»/«X» либо пусто. Это позиции, у которых
срок закупки не назначен вовсе. Ни лист, ни продукт их в год не берут — и это
единственное большое число, которое сегодня не видно ни в одном официальном
итоге.

## 5. Где расхождение с листом всё-таки возможно — и почему это не дефект

Один путь продукта считает уже, чем лист, и делает это намеренно.

Еженедельный отчёт (`build-report.ts:576`) вызывает движок с `asOfDay`: факт
засчитывается, только если дата заключения не позже даты среза
(`fact-date.ts:34-39`). Лист такого гейта не имеет и всегда показывает «на
сейчас». Поэтому отчёт «на четверг», прочитанный в пятницу, будет по факту ниже
листа — на пятничные заключения. Это ровно то обещание, ради которого гейт и
введён; для честного сравнения тот же отчёт держит рядом срез `quarterLive`,
посчитанный без гейта (`build-report.ts:601-603`).

Второй фильтр отчёта — `isUnfundedRow` (`build-report.ts:264-269`) — снимает
строки с плановыми деньгами и пустым/заглушечным годом. Множество то же самое,
что корзина `noYear` движка, так что периметр он не сужает; он лишь выносит эти
строки в отдельную секцию.

## 6. Что вписать в канон

1. **Расхождения нет.** За 2026 год наш расчёт совпадает с официальным СВОДом
   до копейки по всем восьми ГРБС, обоим блокам и району. Утверждение «продукт
   считает больше, потому что берёт строки без года» относится к состоянию кода
   **до 08.08.2026** и на сегодняшних данных ложно.
2. **Правило года — одно и строгое.** Строка входит в годовой срез только при
   явном P, равном году. Фолбэка на N нет. Пустой P — корзина `noYear`, а не
   пропуск в любой срез. Единственная дверь — `emptyYearPolicy` в
   `calc-engine.ts:571`; `'lenient'` считать легаси и в боевых путях не звать.
3. **Год — сумма кварталов, не `total`.** Формулировка адаптера
   (`calc-engine-adapter.ts:164`) обязана оставаться единственным определением
   года: она и есть то, что делает наш год равным листовому.
4. **Три несчитаемых остатка назвать в продукте явно**, потому что они реальны и
   ни в одном официальном итоге не видны: 554 строки без года и квартала на
   294 592,43 тыс. руб.; из них одна на 60 000,00 (УАГЗО, строка 12) со
   способом и деньгами; и 46 строк ЕП на 5 307,21 тыс. руб., где факт в деньгах
   есть, а даты контракта нет.
5. **Единственное законное отличие наших чисел от листовых — срез на дату**
   в еженедельном отчёте. Его следует называть в тексте отчёта прямо, иначе
   читатель примет его за ошибку счёта.
