# Классы дефектов AEMR

## 0. Как читать

Мандат владельца от 22.08.2026 (закон №1) требует: любая жалоба — выборка из
класса, а не случай. Этот документ выводит классы из тридцати претензий недели
(раздел 4 свода) и десяти уроков (раздел 6) и по каждому даёт шесть вещей:
формулировку, инцидент дословной цитатой, первопричину с адресом, полную
перепись носителей, состояние и стража.

**Что такое «носитель».** Место в коде, где класс может проявиться, — не
место, где он уже проявился. Перепись собрана машинным обходом рабочего дерева
22.08.2026, а не по памяти; файлы проверок (`.test.`) из счёта исключены, если
не сказано иное. Где носителей больше тридцати, полный список адресов вынесен в
соседний файл `2026-08-22-defect-classes-carriers.md`.

**Что такое «состояние».** Закрыт — причина устранена в одном месте и стоит
страж. Закрыт частично — устранена часть, названо что осталось. Открыт — причина
жива. Отдельно отмечается случай «правка есть в рабочем дереве, но не
закоммичена»: по мандату (фаза 4) закоммичено не равно выкачено, а
незакоммиченное не равно сделанному тем более.

**Про пустые клетки.** Их нет. Где проверка не проводилась, стоит прямая
строка «не проверено, потому что …».

### К1. Вид навешен на группу селекторов и достаётся каждому элементу перечня

**Формулировка.** Оформление, задуманное для одного вида элементов, объявлено
в наборе селекторов вместе с другими и потому применяется ко всему перечню
сразу; поиск по классам разметки такое правило не находит, потому что классов
разметки в нём нет.

**Инцидент.** Владелец, 21.08.2026 22:12 (сообщение #112):

> изначально и име лв виду

`dad69a8`). Один набор селекторов —

### К4. Выдуманный ноль вместо «не оценено»

**Формулировка.** Отсутствующее значение приводится к нулю в момент чтения, и
дальше по всей цепочке «пусто», «не число» и «настоящий ноль» неотличимы —
метрика показывает уверенный ноль там, где честный ответ «не оценено».

**Инцидент.** Владелец, 18.08.2026 09:57 (#1):

> не обеспечено финансирование - 4 строки - нет понимания из чего сложились
> данные (в каждой строке все данные заполнены и сверены)

и 18.08 20:20 (#28), про метрику, собранную из таких значений:

> почему подвисший контракт всегда пусто?

**Первопричина.** `packages/shared/src/rule-book.ts:27` — `toNumber` честно
возвращает `number | null`, различая «не число» и «ноль». Ложь появляется у
потребителей, и её канонический вид —
`packages/core/src/metrics/economic.ts:83-85`:

```
function num(v: unknown): number {
  return toNumber(v) ?? 0;
}
```

После этой функции пустая ячейка неотличима от ячейки с нулём. Второй вид того
же корня — `packages/core/src/metrics/economic.ts:598-599`: отсутствующий ключ
метрики (`grouped.total.get(planKey)` вернул `undefined`) превращается в ноль и
уходит в дробь как знаменатель.

**Перепись носителей.** Записей `?? 0` в рабочем дереве без файлов проверок —
**584**, из них в вебе **367** (ровно то число, что названо в мандате), в ядре
130, на сервере 62, в общем слое 25. Разбор по назначению строки:

| Род записи | Строк | Ложь ли это |
|---|---:|---|
| Накопитель суммы (`+=`, свёртка, счётчик в карте) | 293 | нет: вклад отсутствующего слагаемого в сумму действительно нулевой |
| Длина, счётчик, порядковый номер | 98 | нет: «нет элементов» и «ноль элементов» — одно и то же |
| Показ числа читателю (подстановка в подпись, доля, дробь) | 46 | **да**: читатель видит ноль, а измерения не было |
| Прочее (сравнения, расстояния, координаты) | 148 | требует поштучного разбора, машинно не разделяется |

Разбор по назначению сделан по форме строки, а не по смыслу переменной, и это
его предел: 148 записей рода «прочее» машинно не классифицируются и требуют
чтения глазами. Полный список адресов всех 584 —
`2026-08-22-defect-classes-carriers.md`, раздел К4.

Отдельный узкий носитель: 11 записей вида `toNumber(…) ?? 0` в 11 файлах — это
места, где различение «пусто / ноль» существовало и было выброшено на месте.
