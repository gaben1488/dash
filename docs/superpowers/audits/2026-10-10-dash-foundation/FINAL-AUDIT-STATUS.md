# Dash — итоговая передача аудита миграции БД и консолидации UI

Дата среза: 10.10.2026. **Статус: аналитический/документационный аудит завершён в доказанном объёме; физическая миграция БД, утверждение макета и развёртывание не проводились.** Этот документ закрывает текущую итерацию исследования, не выдавая внешние эксплуатационные гейты за выполненные. Часть функционального аудита действующего продукта существует в issue [#69](https://github.com/gaben1488/dash/issues/69), кодифицированные исправления — в отдельном draft [#79](https://github.com/gaben1488/dash/pull/79).

## Завершённые действия

1. **Восстановлен и сохранён UI-контракт.** 12 актуальных исходных HTML и один исторический прототип получили распределение по назначению, без подмены существующей геометрии. Прототип использует исходную навигацию и щит `pulse.html` только как оболочку; Пульс как содержимое исключён. Восстановлены 13 маршрутов, семейства «Космос / Камчатка / Минералы» с 39 исходными парами, шесть отделок, 12 осей, OrgStrip и состояние эфира. [Договор консолидации](../../mockups/dash-consolidated/CONSOLIDATION-CONTRACT.md), [проверка интерфейса](../../mockups/dash-consolidated/design-qa.md). Упрощённые экраны — демонстрация, не производственная замена.
2. **Закрыты три дефекта рабочего прототипа.** Reset/Undo одновременно охватывает фильтры, год/месяцы, единицы и неделю; последняя снятая галочка не превращает конкретный выбор в «Все»; CSV корректно хранит точки с запятой/кавычки/переносы, не исполняет текстовые формулы и сохраняет нули/пропуски. Сохраняются исходные компоненты и все 13 маршрутов. **29/29 тестов, 0 ошибок; самостоятельный HTML собрался** в [проверке GitHub Actions №38044005434](https://github.com/gaben1488/dash/actions/runs/38044005434) на Node 22. Полная проверка в браузере новой ревизии не заявлена.
3. **Повторно прочитаны действующие восемь master-книг, без записи.** В рамках строгого предиката «G заполнена, исключены очевидные итоговые строки» — 4092 строки-кандидата, из них P=2026 у 2995, P пуст у 598; это не официальный пересчёт числа закупок. Подтверждены 11 групп буквальных повторов A, два пустых A в УЭР, два случая отображения составного номера как числовой даты в УД. [Методика и числа по каждому ГРБС](LIVE-SHEETS-READ-2026-10-10.md). Исходные закупочные тексты и рабочие файлы в Git не публиковались.
4. **Проверена нынешняя природа хранения.** Source-of-truth — Google Sheets; SQLite/Drizzle обслуживает snapshots, `procurement_rows`, журналы, замечания и настройки. `rowIndex` и `procurement_rows.id` не являются постоянной идентичностью объекта между снимками. `rowRevision` PR #79 — проверка содержимого перед записью, но не транзакция поверх Google и SQL. Many-to-many связь процедуры и строк плана требует доказанного разделения долей. [Гейты миграции и схемы сохранности](DB-MIGRATION-READINESS.md).
5. **Проверен предел затронутого кода.** Новая работа находится в draft PR [#70](https://github.com/gaben1488/dash/pull/70) под `docs/` и в отдельном CI-файле `.github/workflows/dash-preview-checks.yml`. Core/server/web/Google Sheets/SQLite/VPS не изменялись. Реальные исправления ядра PR #79 остаются в своей отдельной ветке, не перенесены этим аудитом.

## Принятое техническое направление на следующий этап

Текущий **SQLite не заменять сейчас**: нет доказанной необходимости другого движка, и выбор не исправит потерянный смысл полей. Возможный PostgreSQL + JSONB — кандидат, если будет нужна многопроцессная запись, ограничения, связанные сущности и управляемые JSON-расширения. MongoDB — альтернативный кандидат для полиморфного сырья, но тоже должен выиграть независимый эксперимент на frozen corpus. Не считать PostgreSQL, MongoDB или полный перенос операционной работы из Sheets в Dash уже одобренными.

Данные разнести логически:
`SourceObservation` (вход без потерь, формула/значение/отображение/версия/notes),
`Activity/Procurement` (UUID + versioned identity mapping),
`Organization` (stable ID, текущие короткие имена и отдельные исторические алиасы),
`Procedure` (many-to-many relations),
`Interpretation` (структурные извлечения из свободного текста с provenance и human override),
`Issue/Decision` (стабильное решение и evidence),
`Snapshot/Release` (воспроизводимый расчёт и ретроспектива).
Это модель ответственности за данные, **не внедрённые таблицы**.

Рекомендуемая очередность: (1) frozen full-source release + SQLite backup/restore, (2) независимый identity crosswalk с очередью неоднозначностей, (3) shadow-импорт и двойной подсчёт с теми же `rules_version`, (4) fault-injection и безопасная запись, (5) только затем архитектурное решение, промоушен и rollback. Пропускать этапы ради визуального окончания задачи запрещено.

## Чего не делать с результатом

- Не сливать PR #70 как замену всей пользовательской части: в нём fake-row demo; source HTML и production страницы отдельны.
- Не сливать #79 только потому, что root CI зелёный: готовность concurrent write требует реального replay/восстановления.
- Не смешивать `G empty` с пустым формульным хвостом, `P empty` с отсутствием финансирования, повтор номера с дублем расходов, отсутствующий Drive reply с отсутствием обсуждения.
- Не публиковать исходные ведомственные XLSX, приватные Sheets snapshots, секреты и данные сотрудников в открытом репозитории.
- Не утверждать «100% миграция» до физической сверки и восстановления.

**Итог:** текущая исследовательская итерация закрыта передачей исходников, реально исправленного и протестированного демо, живой разведки и исполнимого плана миграции. Production migration остаётся самостоятельной задачей с внешними ограничениями и отдельной приёмкой.


## Дополнение G1: исполняемый crosswalk-контракт (последняя проверка 10.10.2026)

[Draft PR #91](https://github.com/gaben1488/dash/pull/91) добавляет отдельный, не подключённый к production инструмент
\`tools/db-migration/identity-crosswalk.mjs\` и CLI для сравнения **двух уже замороженных снимков**.
Он не назначает UUID на основании номера A, предмета или положения строки:
автоматически связывает только ранее подтверждённый уникальный \`entityId\`
либо применяет явное решение с проверкой обеих SHA-256 версий исходной строки.
Повтор A, повтор ID, изменения данных после подтверждения, конкурирующие решения
и невозможность однозначной привязки видны как конфликт/очередь проверки.

CI независимого инструмента:
[Dash DB identity audit checks](https://github.com/gaben1488/dash/actions/workflows/dash-db-identity-checks.yml)
— успешная проверка тестовых сценариев и безопасного CLI; конкретный commit/run
нужно сверять на PR #91. Синтетические тесты **не** подтверждают, что G1 прошёл
для реальных восьми книг: отсутствуют полный G0 source snapshot A:AH,
версионированные raw/formula/display/note, решение коллизий и восстановленная
копия SQLite. Отдельно сохранён шаблон безопасного локального запуска в
[README инструмента](https://github.com/gaben1488/dash/tree/codex/dash-db-identity-crosswalk-20261010/tools/db-migration).

Это расширяет **исследовательскую готовность**: остаются прежними статусы G0–G4
из таблицы выше. Без этих гейтов ни одна СУБД и ни один разовый импорт
не могут быть названы безопасно завершённой миграцией.
