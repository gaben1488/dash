# Матрица пересечений сигналов — восемь книг ГРБС (21.08.2026)

Что сделано: предикаты всех построчных проверок продукта выписаны из кода, затем
**исполнены самим кодом продукта** (модули `packages/core` и `packages/shared`
импортированы как есть, ничего не переписывалось) по живым дампам восьми книг
ГРБС. На выходе — матрица «строка книги × сработавшие ключи», счёт по каждому
ключу и множество строк, выпадающих из годового расчёта, с причиной для каждой.

Сокращения путей: `core/` = `packages/core/src`, `shared/` = `packages/shared/src`.

Данные: `E:/aemr-dumps/book-dumps/grbs-*.json` (снимок 18.08.2026), рабочий лист
каждой книги по `shared/department-registry.ts` — «ВСЕ» у УЭР, УАГЗО, УД, УКСиМП,
УО; именной лист у УИО, УФБП, УДТХ. СВОД исключён.

Чтение ячеек воспроизводит боевой конвейер: `values.batchGet` с
`valueRenderOption=UNFORMATTED_VALUE` и `dateTimeRenderOption=FORMATTED_STRING`
(`server/services/google-sheets.ts:221`) — числа числами, даты строкой
«дд.мм.гггг», хвостовые пустые ячейки строки отброшены.

Универсум строк — тот же, что у детектора сигналов конвейера
(`core/pipeline/orchestrator.ts:848` + `:866`): срез шапки в `DEPT_HEADER_ROWS = 3`
строки, отсев строк короче пяти ячеек, отсев мета-строк по `isMetaRow`
(«итого|всего|раздел|наименование» с якорем начала строки, `shared/column-map.ts:279`)
и отсев строк, где пусты все ячейки.

Все деньги — **в тысячах рублей**, как в самих книгах.

## 1. Предикаты построчных сигналов

### 1.1 Семейство A — `RowSignals` (`core/pipeline/signals.ts:364`)

Общие величины строки, на которых стоят все предикаты:

| Величина | Как считается |
|---|---|
| `planTotal` | `K` через `sheetNumber` (пробелы-разряды, запятая-десятичная); мусор → NaN |
| `factTotal` | `Y`, если он не NaN и не 0; иначе `V+W+X` (NaN как 0) |
| `planDay` / `factDay` | номер суток из `N` / `Q` через `dayNumberOf` (дд.мм.гггг, serial 40000–60000, ISO), TZ-инвариантно |
| `todayDay` | номер суток «сегодня» по локальным компонентам |
| `isEP` | текст `L` в нижнем регистре содержит «еп» либо «единствен» |
| `hasFactAmounts` | `factTotal > 0` |
| `hasFactDate` | `factDay !== null` |
| `hasFact` | `hasFactAmounts || hasFactDate` |
| `economyFlag` | `AD` в нижнем регистре ровно «да» либо «yes» |
| `economyFlagDetermined` | `economyFlag` либо `AD` ровно «нет»/«no» |
| `isLegitimateEP` | `M` содержит «монополист/монопол/естественн/губернатор/поручен/региональный оператор», **либо** `M` цитирует п.1, 6, 8 или 29 ч.1 ст.93 регулярным выражением `/п\.?\s*(\d{1,2})\s*ч\.?\s*1\s*ст\.?\s*93/` |

Двадцать семь живых сигналов:

| Ключ | Имя (словарь продукта) | Точное условие | Гейты и подавления |
|---|---|---|---|
| `signed` | Подписан | `hasFactDate` | — |
| `hasFact` | Есть факт | `factTotal > 0 \|\| hasFactDate` | — |
| `economyFlag` | Экономия | `AD === «да»/«yes»` | — |
| `overdue` | Просрочен | `planDay !== null && planDay − todayDay < 0 && !hasFact` | текст U/AE/AF не читается (канон п.27) |
| `planSoon` | Скоро срок | `0 ≤ planDay − todayDay ≤ 14 && !hasFact` | — |
| `economyConflict` | Конфликт флага экономии | при `planTotal > 0 && factTotal > 0`: (а) `economyFlag && factTotal ≥ planTotal`; либо (б) `!economyFlagDetermined && factTotal < planTotal && 15 % < экономия ≤ 25 %` | (б) не считается для ЕП; **верхняя граница 25 % — подавление дубля с `highEconomy`** (`signals.ts:492`) |
| `epRisk` | ЕП-риск | `isEP && planTotal > 600 (тыс.) && !isLegitimateEP` | **гасится законным основанием** (монополии, поручения губернатора, пп.1/6/8/29 ст.93) |
| `dataQuality` | Пустые обязательные поля | строка данных **и** (`hasFactDate` либо `planDay < todayDay`) **и** пусто хотя бы одно из `D`, `K`, `L` | гейт «строка исполняется либо срок прошёл»: чистые будущие планы не проверяются |
| `formulaBroken` | Ошибка формулы | любая ячейка строки содержит `#REF/#VALUE/#N/A/#NAME/#DIV/0/#NULL/#NUM/#ERROR` | — |
| `highEconomy` | Высокая экономия > 25 % | `!isEP && planTotal > 0 && factTotal > 0 && (planTotal − factTotal)/planTotal × 100 > 25` | **только конкурентные способы** |
| `lowCompetition` | Низкая конкуренция < 2 % | `!isEP && planTotal > 0 && factTotal > 0 && 0 ≤ экономия % < 2 && factTotal ≠ planTotal` | **только конкурентные**; **гасится точным равенством план = факт** (артефакт заполнения) |
| `earlyClosure` | Раннее закрытие | при обеих датах: (а) год факта < года плана **и** `planDay − factDay > 30`; либо (б) `planDay − factDay > 180 && planDay < todayDay && !isEP` | ветка (б) — **только конкурентные** (гейт 18.08, В-9); ветка смены года гейта не имеет |
| `factExceedsPlan` | Факт больше плана | `planTotal > 0 && factTotal > planTotal × 1,005` | допуск 0,5 % против округлительного шума |
| `epFactDeviation` | По ЕП факт не равен плану | `isEP && planTotal > 0 && factTotal > 0 && \|factTotal − planTotal\| > planTotal × 0,005` | **зеркальный гейт: живёт только на ЕП** |
| `factWithoutDate` | Закупка в течение года | `hasFactAmounts && !hasFactDate` | — |
| `dateWithoutFact` | Факт дата без сумм | `hasFactDate && !hasFactAmounts` | — |
| `factDateBeforePlan` | Факт раньше плановой даты | `0 < planDay − factDay ≤ 30 && !isEP` | **только конкурентные**; верхняя граница 30 дней **разводит с `earlyClosure`** |
| `futureFactDate` | Дата факта в будущем | `factDay > todayDay` | — |
| `planWithoutExecution` | План без исполнения | `planTotal > 0 && !hasFact && !overdue && !planYearMissing` и далее: при `planDay !== null` — `todayDay − planDay > 30`; при пустой `N` — только с апреля (месяц ≥ 3) | **гасится `overdue` и `planYearMissing`** (первопричина главнее следствия, `signals.ts:697`) |
| `epJustificationMissing` | ЕП без обоснования | `isEP && isAbsentCell(M) && planTotal > 0` | маркер отсутствия «X/х/тире» считается незаполненностью (канон п.62) |
| `methodReasonMismatch` | Метод не соответствует обоснованию | `isEP` и кластер `M` не EMPTY/UNMAPPED и кластер помечен процедурным (`EP_SMALL_EL_PURCH`) | — |
| `unmappedReasonEP` | Обоснование ЕП не распознано | `isEP` и кластер `M` = `UNMAPPED` либо `EP_CURRENT_LAW` | — |
| `budgetUnderallocation` | Факт без планового бюджета | `factTotal > 0 && (planTotal NaN \|\| planTotal === 0)` | — |
| `budgetSourceMissing` | Источники бюджета не указаны | `planTotal > 0` и все `H/I/J` пусты либо нули (колонки из `PLAN_SOURCE_COLUMNS`) | — |
| `planYearMissing` | Не обеспечено финансированием | `N` пуста/маркер отсутствия **и** `P` пуста/«х»/«x»/«-» **и** `L` не пуста **и** `planTotal > 0` | **решает рукописная N**, а не производная P (канон п.93/45, фикс п.98а) |
| `derivedFormulaBroken` | Сломана формула даты | `L` не пуста и `planTotal > 0` и (пара план сломана **или** пара факт сломана): план — `planDay !== null && (квартал O вне 1..4 либо P пуста)`, либо `N` пуста при заполненных O/P; факт — `factDay !== null && (R пуста либо S пуста)`, либо `Q` пуста при заполненных R/S | — |
| `factQuarterMissing` | Факт без планового квартала | `hasFactDate && квартал O вне 1..4 && !derivedFormulaBroken && !planYearMissing` | **остаточная страховка: гасится обеими первопричинами** (`signals.ts:659`) |

Восемь вечно-ложных полей (`planning`, `notDue`, `canceled`, `financeDelay`,
`singleParticipant`, `stalledContract`, `budgetMismatch`, `tdWithProgram`)
в матрицу не пишутся: `detectSignals` выставляет их константой `false`
(`signals.ts:41–59`).

### 1.2 Подавления, выписанные отдельно (п.34)

Ровно семь мест, где один сигнал гасит другой или сам себя ограничивает:

1. `planYearMissing` → гасит `planWithoutExecution` (`signals.ts:697`).
2. `planYearMissing` **и** `derivedFormulaBroken` → гасят `factQuarterMissing` (`signals.ts:659–660`).
3. `highEconomy` (порог 25 %) → обрезает сверху ветку (б) `economyConflict` (`signals.ts:492`).
4. Точное равенство `factTotal === planTotal` → гасит `lowCompetition` (`signals.ts:538`).
5. `earlyClosure` (порог 30 дней) → разводит себя с `factDateBeforePlan` (`signals.ts:683`).
6. `overdue` → гасит `planWithoutExecution` (`signals.ts:697`).
7. `isLegitimateEP` → гасит `epRisk` (`signals.ts:451`).

И пять гейтов по способу закупки: `highEconomy`, `lowCompetition`,
`factDateBeforePlan`, ветка «>180 дней» у `earlyClosure` и ветка (б)
`economyConflict` не считаются для ЕП; `epFactDeviation` — наоборот, живёт
только на ЕП.

## 2. Как считалось (воспроизводимость)

Предикаты не переписывались: скрипт-прогон **импортирует боевые модули**
`packages/core/src/index.ts` и `packages/shared/src/index.ts` и зовёт
`detectSignals`, `classifyRows` + `validateData(RULE_BOOK)`,
`detectCommentInconsistencies`, `detectDateFormatIssues`, `detectCellHygiene`,
`detectSubordinateNameHygiene`, `checkSequenceIntegrity`, `isYearlongStageRow`,
`epGradeOfCluster`, `standardRowFilter`. Код репозитория не менялся; скрипты
прогона лежат вне репозитория (`ov_extract.py`, `ov_matrix.ts` в рабочем
каталоге сессии).

Дата прогона — 21.08.2026, 04:39; датные сигналы (`overdue`, `planSoon`,
`futureFactDate`, `planWithoutExecution`, `earlyClosure`) зависят от этого дня.

**К какому состоянию кода привязаны числа.** Рабочее дерево на `2d9442e` в
04:39. В 04:44 и 04:47 того же утра параллельная работа тронула `rule-book.ts`
и `signals.ts` — в частности, `economyConflict` там разделяется надвое: случай
(а) остаётся конфликтом, случай (б) выносится в новое поле
`economyFlagUndetermined`. Строка `signal:economyConflict` = 10 в §4 относится
к ДОразделительной редакции (оба случая в одном поле); после переплавки её
надо пересчитать. Остальные предикаты правкой не тронуты.

Три независимые сверки, подтверждающие, что универсум и предикаты совпали
с боевыми:

1. **8 476 строк** универсума — ровно то число, которым помечена живая проверка
   в самом коде (`signals.ts:486`: «8476 строк»).
2. **2 979 строк с датой факта** — то же число, что в комментарии к
   `factQuarterMissing` (`signals.ts:658`), и сам сигнал здесь, как там,
   даёт **ноль** срабатываний.
3. **УЭР: 5 строк без года плана на 589,94 тыс.** — совпадает со сверкой лимита
   УЭР 06.08.2026 (`signals.ts:144`, «5 строк на 589,93 тыс.»).
   Плюс два точечных случая: УАГЗО стр.9 № 42 (план 3 078,96 тыс., ЕП) `epRisk`
   НЕ получает — гейт «п.6 ч.1 ст.93» работает; УД стр.101 получает
   `earlyClosure` по смене года — как и описано в коде.

**Про `filter:score<3` — важное.** Все 4 590 отвергнутых строк пусты полностью:
нет «№ п/п», нет предмета, нет плановых и фактических денег. Ненулевых среди
них — **ноль**. Это простыня листа: диапазон дочитан до последней заполненной
ячейки в дальней колонке, а формулы `K`, `Y`, `Z`, `AA`, `AB`, `AC` в пустых
строках возвращают ноль, поэтому строка не выглядит «полностью пустой» для
проверки на пустоту. Ответ на вопрос владельца «925 из 994 у УАГЗО»:
**фильтр не потерял ни одной закупки**, он отсеял канву.

## 6. Что это меняет (без правок кода)

1. **`factWithoutDate` и `yearlong:stage` — один класс строк, две
   противоположные оценки.** 46 строк из 46. Решение владельцу: либо снять
   замечание `fact_without_date` и оставить корзину-стадию, либо наоборот.
   Пока живут оба, читатель двух вкладок получает про одну строку «дефект» и
   «законная стадия».
2. **Три карточки на одну строку ЕП без даты факта.** Те же 46 строк несут
   `epFactDeviation` (по ЕП факт не равен плану). Механизм один: договор
   заключён «в течение года», дата не проставлена, суммы разошлись.
3. **Гигиена текста дробится на роды там, где дефект один.** 181 ячейка несёт
   и краевой пробел, и невидимый символ. Сводка правила `text_hygiene` считает
   роды, а не ячейки — счёт «два дефекта» на одну правку.
4. **Дорогая невидимка живёт в двух книгах.** УАГЗО (60 000,00 тыс.) и УДТХ
   (22 875,03 тыс.) — две строки, каждая дороже всего годового плана УЭР,
   выпадают из официального счёта из-за пустого года плана.
5. **`standardRowFilter` чист.** Претензия «фильтр теряет строки» не
   подтверждается: все 4 590 отвергнутых строк пусты по всем содержательным
   колонкам.
6. **Семь построчных сигналов и пять правил листа на живых книгах молчат.**
   Это не повод их удалять (они ловят редкие классы), но повод не считать их
   работающим покрытием: сегодня продукт на книгах ГРБС держится на
   двадцати сигналах из двадцати семи.
