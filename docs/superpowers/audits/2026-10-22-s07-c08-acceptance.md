# Dash: сквозная приёмка источников и воспроизводимости (22.10.2026)

## Статус / назначение

Этот документ **не** является вторым реестром задач или подтверждением production-приёмки.
Канонические задачи: **S07.01** (скрипты, журнал, запуски) и **C08.02** (воспроизводимый расчёт).
В календаре «142 задачи» это соответственно **№17** и **№20**. «Задача 20 / S07.01»
в некоторых чатах относится к старой нумерации.

Кодовые кандидаты: [PR #137](https://github.com/gaben1488/dash/pull/137) (история),
[PR #157](https://github.com/gaben1488/dash/pull/157) (паспорт расчёта).
Оба PR должны оставаться draft до независимой приёмки. Не переносить зелёный CI
на конкретный VPS либо Apps Script, пока не получен результат эксплуатации.

## Периметр зависимостей: один источник, несколько способов наблюдения

| Слой | Действующая точка / граница |
| --- | --- |
| 8 первичных книг ГРБС | собственные рабочие листы, формулы, валидации, скрытые `_ChangeLog`; время книг `Asia/Kamchatka` |
| Журнал правок | `changelog-source.ts` — общий fetch для `/api/changes`, `provenance-journal.ts`, `/api/workload`; разные парсеры, общее сырьё |
| События вне Apps Script | `webhook-queue.ts`, `source-refresh.ts`, `sheet-fingerprint.ts`, `live-diff.ts` и `book-watermark.ts` |
| Общий рассказ | `/api/change-story` сводит журнал и сравнение снимков; эфир не должен дублироваться внутри ответа |
| Расчёт | `runPipeline` + `getActiveRules`; `snapshot.ts` сохраняет результат и существующие строки-атомы |
| Архив/потребители | `getSnapshotAtOrBefore`, UI/Пульс/СВОД, `/api/report`, `/api/report-releases` и Word |

**Не создавать:** вторую очередь webhook, вторую БД журнала, новый «основной»
источник закупок или копию 8 первичных книг ради встраивания паспортов.

## Факты с live-read 22.10

- В каждой из восьми первичных книг существует `_ChangeLog`, но наличие листа
  **не равно** доказанной установке и исправности триггеров Apps Script.
- В живых журналах встречаются `ДД.ММ.ГГГГ`, время с неполным нулём в часах,
  `ДД.ММ.ГГГГ, чч:мм:сс`, 6- и 8-колоночные записи, пакетные/структурные операции.
- В части 6-колоночных записей нет бизнес-ключа закупки; не восстанавливать его
  из номера строки или текущего соседства.
- Удаление строк, API-правки и массовые изменения не гарантируются одним
  `onEdit`. Нужны снимки до/после, очередь событий и честная диагностика пропусков.

## Gate S07.01: пять контролируемых доказательств

1. Восемь реальных Apps Script проектов: projectId, список файлов и версий,
   простые и установленные триггеры (тип/функция/владелец), доступы, журналы
   Executions/ошибок и расписания. Если Scripts API не подключён, поставить
   `BLOCKED: trigger inventory unavailable`, а не `PASS`.
2. На **копиях**, не в production: одиночная правка, вставка нескольких ячеек,
   правка формулы/валидации, сортировка/вставка/удаление строки,
   изменение через Apps Script, изменение через Sheets API.
   Для каждой операции — source revision, before/after diff, наблюдавшийся
   `_ChangeLog`/webhook, автор (достоверен / неизвестен), число пропусков.
3. После рестарта: повтор уведомления не увеличивает число событий;
   ошибку очереди нельзя подтверждать как обработанную. Последний подтверждённый
   снимок сохраняется отдельно от последней неуспешной попытки.
4. По двум существующим потребителям журнала (`/api/changes` и
   `/api/change-story`) подтвердить одинаковые реальные события в общем
   периметре источников, но не требовать равенства там, где у одного события
   нет бизнес-ключа либо время указано лишь с точностью до даты.
5. CI exact head + независимое review + контролируемая установка, real
   readback, восстановление предыдущей версии. Результат негативных тестов
   обязателен, «зелёный CI» один не достаточен.

## Gate C08.02: паспорт одного расчётного контекста

Минимальный паспорт **сохраняется внутри существующего** `snapshots.data`:
идентификатор снимка, дата/период, source IDs/наблюдённые версии и момент
чтения, хеш использованных входов/правил/карты/выходов, SHA кода при
доказанном происхождении, статус полноты и причины неопределённости.

Контракт `dash-calculation-evidence-v1` честно фиксирует только **input/output
attestation**, а не полное воспроизведение. Для полноценного DoD ещё нужны:
сохранённые точные внешние входы (включая служебные формулы и официальный
СВОД), code SHA фактически установленного образа, сопоставление исходных
ревизий в окне чтения, независимый offline frozen replay, а также сверка
manifest/release_id Word с тем же snapshot/rules_version и восстановление
после restart/rollback. Пока эти условия не подтверждены,
`fullReplayVerified=false`. Дата старого источника не превращается в новую.

### Негативные сценарии для конечной приёмки

- Подмена одной архивной строки/суммы/формулы либо версии правил =>
  конкретный mismatch или `unknown`, но никогда `PASS`.
- Сбой одной книги из восьми, источник-зеркало вместо первички, потеря
  хеша/времени чтения/кода => частичный статус, без нуля вместо неизвестного.
- Две обработки того же webhook => без дублирующих историй/нового выпуска.
- Повтор отчёта со старыми `snapshot_id/rules_version` => ровно прежний
  комплект Word или объяснимый отказ, без пересчёта на сегодняшних данных.
- Откат к предыдущему образу => сохранение прежних подтверждённых снимков и
  Word, отсутствие ретроактивного изменения данных ГРБС.

## Границы работ

**Запрещено без отдельного проверенного diff и разрешения:** удаление листов,
смена структуры книг, перепривязка первичных источников, перенос владения
данными в Dash, восстановление удалённого листа `Settings` ради старого
`etalon-sync`, подмена исторических статусов и автоматический merge/deploy.

Приёмка = наличие точного SHA/CI, фактически установленных Apps Script/образа,
проверенного snapshot/release и восстановимого пути назад. Пока чего-либо
нет — указывать блокер, не расширять проект новой инфраструктурой.
