# Ритуал «прогулка пользователя» — обязательный QA-проход после каждой фазы

> Происхождение (2026-07-14, слово пользователя): «мы нашли много бреда и ошибок,
> но во время твоего поиска багов это не находилось. стоит эволюционировать и
> избавить меня от лишнего труда». Диагноз: bug-hunt'ы читали КОД и находили
> кодовые баги; продуктовый бред (мусорная валидация, липовые 100%, латиница в
> подписях, мёртвые кнопки) виден только при ИСПОЛЬЗОВАНИИ с доменными
> ожиданиями. Единственный проход, находивший этот класс — QA D1-D20 (13.07),
> потому что ходил по UI с реальными данными против эталона.

## Правило

После каждой фазы мастер-плана (и перед любым «готово» пользователю) — агент с
браузером проходит ВСЕ страницы на РЕАЛЬНЫХ данных и проверяет по чек-листу.
Находки — в реестр дефектов с доказательствами (скриншот/значения). Это НЕ
замена статическому bug-hunt'у — это второй, обязательный, глаз.

## Чек-лист прохода (по каждой странице)

1. **Каждое видимое число** — откуда оно? Сверить выборочно с каноном
   (СВОД/эталонный отчёт/ручной счёт по строкам). Особые подозреваемые:
   проценты 0%/100% (вырожденность = чаще всего баг атрибуции), суммы-нули,
   «аккуратные» числа.
2. **Каждый видимый текст** — человеческий русский? Ни латиницы-ключей, ни
   EP_*/snake_case, ни ярлыков-калек. Термины = термины предметника (ГРБС,
   ПБС, план-график), не программистские.
3. **Каждый контрол кликнуть** — кнопки, фильтры, сортировки, раскрытия.
   Мёртвый контрол/вечный спиннер/молчаливый фейл = дефект. Консоль браузера
   на ошибки после каждого клика.
4. **Каждый фильтр** — реально фильтрует? Числа виджетов уважают выбранный
   срез (год/ГРБС/бюджет)? Сумма частей = итогу?
5. **Согласованность страниц** — одна и та же величина на двух страницах
   совпадает? (класс D1: Пульт vs Реестр из разных источников).
6. **Ошибки/пустые состояния** — сообщение об ошибке человеческое и говорит,
   что делать? Пустая таблица объясняет почему?
7. **Домен-нюх**: у 8 ГРБС разный масштаб (УО ~1000 строк, УАГЗО ~5);
   исполнение кварталов не бывает 100% у всех; экономия ЕП = 0 по построению;
   отрицательное отклонение в днях = раньше срока (норма, не ошибка).

## Классы болезней (найденные — искать братьев везде)

- **Два пути к одному ресурсу** (D1, валидация-vs-загрузчик): любое чтение
  одного источника двумя маршрутами. При находке — единый резолвер.
- **Ad-hoc правила в роутах** (валидатор с колонками-наугад): проверки данных
  только канонические (detectSignals/CHECK_REGISTRY), никогда в роуте.
- **Сырые ключи в UI** (D15): рендер значения без productLabel.
- **Вырожденные проценты** (D8/D16): счётчик и гейт из разных множеств.
- **Легаси-имена** (ШДЮ): переименованный источник, живущий под старым именем.

## Механика

Агент: browser-harness/Claude Browser + реальный дев-сервер (.env креды).
Прогон ~30-60 мин. Выход: docs/superpowers/qa/walkthrough_<дата>.md — таблица
«страница | что проверил | ок/дефект | доказательство». Дефекты → в реестр
дефектов мастер-плана с категорией из классов выше.
