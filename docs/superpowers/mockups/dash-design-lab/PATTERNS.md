# ДЭШ — каталог проверяемых UI-приёмов

**Статус:** разработческий стенд поверх PR #83; не production-замена и не акт дизайнерской приёмки. Файлы: PatternGallery.tsx, recipes.ts, patterns.css и тесты в packages/web/src/pages/design-lab/. Вход: #/kit/lab → «Компоненты и практики». Все демонстрационные строки вымышлены.

## Почему это не вторая дизайн-система

В Dash уже существуют рабочие Button, Chip, Card, Stat, Origin, FreshnessMark, DataTable, Segmented, EmptyState, типографические токены и страница Kit. Они остаются единственными домами соответствующего поведения. Каталог **не** создаёт ButtonV2, не копирует реестр и не выдаёт демо-модель за API рабочих данных. Он показывает сочетания компонентов и объясняет, когда их применять, а когда запрещать.

Справочник исходных компонентов — COMPONENT_INDEX, примеры — UI_RECIPES. Каждая запись содержит вопрос человека, решение, антипример, минимум три критерия приёмки, связи с настоящими файлами и воспроизводимую кодовую заготовку. Проверка путей закреплена тестом. Экспериментальные темы применяются **внутри сцены**, не на документе: действующая тема Dash, бюджетные цвета, маршруты и источники не затрагиваются.

## Восемь приёмов

| Рецепт | От какого дефекта защищает | Что показывается |
|---|---|---|
| Число с доказательством | безадресная цифра без периода | Stat, Origin, FreshnessMark, неизвестная база |
| Строка и её проблема | обезличенные алерты и потеря составного номера | двойной адрес, формула, RowSignals |
| Провести через исправление | скоринг без следующего шага | причина → источник → проверка → только учебное завершение |
| Фильтры без подмены | пустой отбор тайком становится всеми строками | aria-pressed, честный пересчёт и сброс |
| Изменение без подмены версии | скрытие баннера считается обновлением | увидено → прочитано → применено, отказ сохраняет старое |
| Пустота ≠ ноль ≠ сбой | молчаливый отказ чтения | EmptyState с разными причиной и действием |
| Типографика цифр | рассинхрон дат, единиц и разрядов | ds-text, tabular-nums, плотности |
| Материал поверх геометрии | лак везде, потерянные исходные барабаны | отделка по роли, смысловые краски отдельно |

## Как добавлять приём

1. Найти **первичный рабочий компонент**, его вызывающих, токены, тесты и исходный HTML. Сначала оценить повторное использование.
2. Назвать явное назначение словами исполнителя: «Откуда число», «Что делать», «Как не потерять выбор». Само по себе красивое стекло не является назначением.
3. Добавить UI_RECIPES с устойчивым уникальным id, полями answer, mistake, criteria, components, code, честным status. Если источник отсутствует, тест должен падать.
4. Добавить **локальный** работающий пример в LiveRecipe. Никаких запросов к backend, изменений таблиц, подтверждений «исправлено» без персистентной гарантии. Действия подписывать ДЕМО.
5. Проверить отказ, пустоту, длинный текст, узкую ширину, клавиатуру, скринридер, свет/ночь, плотность и reduced motion. Проверять поведение, а не только наличие текста.
6. Для изменения production создавать **отдельный** адресный PR с characterization-тестом прежнего поведения. Исходные барабан, OrgStrip, Header, API и расчёты не меняются библиотечным PR.

## Честные следующие ограничения

- **Исторические hardcoded-цвета.** Например, действующий EmptyState.tsx всё ещё использует Tailwind blue/red/gray напрямую; в Button, Stat и Chip роли цвета уже управляются токенами. Исправление требует отдельного регрессионного теста и не считается выполненным здесь.
- **Подлинные материалы.** Схематический цветовой предмет в лаборатории не равен полной физике исходного otdelki.html; горизонтальный цветовой стенд не заменяет трёхрядный барабан pulse.html. Не копировать сцены как production-разметку.
- **Дизайн-решения.** Новые варианты и наборы не становятся автоматически принятым визуалом. Источник и код нуждаются в прослеживаемой привязке к решению.
- **Доступность и масштаб.** Для семи экспериментальных подложек оба режима теперь имеют автоматический контроль читаемости основного и второстепенного текста. Сильные рамки интерактивных контролов берутся из контрастного muted-цвета; мягкие декоративные линии не обещают 3:1. По-прежнему требуется браузерная проверка 390/768/1280, 200% увеличения, смешанных эффектов, Popover, клавиатуры и reduced motion. JSDOM-тест не подтверждает качество вёрстки.

## Проверки

В режиме разработки запустить pnpm -F @aemr/web dev и открыть #/kit/lab.

Из корня репозитория выполнить команды по очереди:

    pnpm -F @aemr/web exec vitest run src/pages/design-lab/recipes.test.ts src/pages/design-lab/PatternGallery.test.tsx
    pnpm lint
    pnpm -r --workspace-concurrency=1 exec tsc --noEmit
    pnpm -r test
    pnpm -F @aemr/web build

После CI проверить отсутствие лаборатории в production entry, отсутствие переписанных Header/OrgStrip/Store и запросов к рабочим API. Если любой гейт красный — результат не объявляется принятым.

**Правило релиза:** производство продвигается только после подтверждения старого поведения. Библиотека не определяет KPI, не вмешивается в данные и не скрывает ошибки красивой отделкой.
