# ДЭШ — каталог проверяемых UI-приёмов

**Статус:** разработческий стенд поверх PR #83; не production-замена и не акт дизайнерской приёмки. Файлы: PatternGallery.tsx, recipes.ts, patterns.css и тесты в packages/web/src/pages/design-lab/. Вход: #/kit/lab → «Компоненты и практики». Все демонстрационные строки вымышлены.

## Почему это не вторая дизайн-система

В Dash уже существуют рабочие Button, Chip, Card, Stat, Origin, FreshnessMark, DataTable, Segmented, EmptyState, типографические токены и страница Kit. Они остаются единственными домами соответствующего поведения. Каталог **не** создаёт ButtonV2, не копирует реестр и не выдаёт демо-модель за API рабочих данных. Он показывает сочетания компонентов и объясняет, когда их применять, а когда запрещать.

Справочник исходных компонентов — COMPONENT_INDEX, примеры — UI_RECIPES. Каждая запись содержит вопрос человека, решение, антипример, минимум три критерия приёмки, связи с настоящими файлами и воспроизводимую кодовую заготовку. Проверка путей закреплена тестом. Экспериментальные темы применяются **внутри сцены**, не на документе: действующая тема Dash, бюджетные цвета, маршруты и источники не затрагиваются.

## Четырнадцать приёмов

| Рецепт | От какого дефекта защищает | Что показывается |
|---|---|---|
| Число с доказательством | безадресная цифра без периода | Stat, Origin, FreshnessMark, неизвестная база |
| Строка и её проблема | обезличенные алерты и потеря составного номера | двойной адрес, формула, RowSignals |
| Провести через исправление | скоринг без следующего шага | причина → источник → проверка → только учебное завершение |
| Фильтры без подмены | пустой отбор тайком становится всеми строками | aria-pressed, честный пересчёт и сброс |
| Изменение без подмены версии | скрытие баннера считается обновлением | увидено → прочитано → применено, отказ сохраняет старое |
| Пустота ≠ ноль ≠ сбой | молчаливый отказ чтения | EmptyState с разными причиной и действием |
| Типографика цифр | рассинхрон дат, единиц и разрядов | ds-text, tabular-nums, плотности |
| Материал поверх геометрии | лак везде, потерянные исходные барабаны | отделка по роли, смысловые краски отдельно |
| Действие без ложного успеха | кнопка объявляет успех раньше записи | стадии, подтверждение, отмена опасного действия |
| Один главный сигнал | пять тревожных бейджей без следующей операции | приоритет, источник, раскрываемая доказательность |
| Ноль или неизвестно | сбой чтения становится нулём | разные значения и причины отсутствия |
| Единицы без изменения данных | переключатель тыс./млн подменяет сами числа | один источник, форматирование и контроль суммы |
| Длинное название | троеточие скрывает учреждение и сумму | полное имя, прокрутка и читаемые разряды |
| Факт или предположение | эвристика выглядит подтверждённым фактом | отдельный статус и шаг проверки |

## Как добавлять приём

1. Найти **первичный рабочий компонент**, его вызывающих, токены, тесты и исходный HTML. Сначала оценить повторное использование.
2. Назвать явное назначение словами исполнителя: «Откуда число», «Что делать», «Как не потерять выбор». Само по себе красивое стекло не является назначением.
3. Добавить UI_RECIPES с устойчивым уникальным id, полями answer, mistake, criteria, components, code, честным status. Если источник отсутствует, тест должен падать.
4. Добавить **локальный** работающий пример в LiveRecipe. Никаких запросов к backend, изменений таблиц, подтверждений «исправлено» без персистентной гарантии. Действия подписывать ДЕМО.
5. Проверить отказ, пустоту, длинный текст, узкую ширину, клавиатуру, скринридер, свет/ночь, плотность и reduced motion. Проверять поведение, а не только наличие текста.
6. Для изменения production создавать **отдельный** адресный PR с characterization-тестом прежнего поведения. Исходные барабан, OrgStrip, Header, API и расчёты не меняются библиотечным PR.

## Честные следующие ограничения

- **Исторические hardcoded-цвета.** Например, действующий EmptyState.tsx всё ещё использует Tailwind blue/red/gray напрямую; в Button, Stat и Chip роли цвета уже управляются токенами. Исправление требует отдельного регрессионного теста и не считается выполненным здесь.
- **Подлинные материалы.** Схематический цветовой предмет в лаборатории не равен полной физике исходного otdelki.html; горизонтальный цветовой стенд не заменяет трёхрядный барабан pulse.html. Не копировать сцены как production-разметку.
- **Дизайн-решения.** Новые варианты и наборы не становятся автоматически принятым визуалом. Источник и код нуждаются в прослеживаемой привязке к решению.
- **Доступность и масштаб.** Для семи экспериментальных подложек оба режима теперь имеют автоматический контроль читаемости основного и второстепенного текста. Сильные рамки интерактивных контролов берутся из контрастного muted-цвета; мягкие декоративные линии не обещают 3:1. По-прежнему требуется браузерная проверка 390/768/1280, 200% увеличения, смешанных эффектов, Popover, клавиатуры и reduced motion. JSDOM-тест не подтверждает качество вёрстки.

## Проверки

В режиме разработки запустить pnpm -F @aemr/web dev и открыть #/kit/lab.

Из корня репозитория выполнить команды по очереди:

    pnpm -F @aemr/web exec vitest run src/pages/design-lab/recipes.test.ts src/pages/design-lab/PatternGallery.test.tsx
    pnpm lint
    pnpm -r --workspace-concurrency=1 exec tsc --noEmit
    pnpm -r test
    pnpm -F @aemr/web build

После CI проверить отсутствие лаборатории в production entry, отсутствие переписанных Header/OrgStrip/Store и запросов к рабочим API. Если любой гейт красный — результат не объявляется принятым.

**Правило релиза:** производство продвигается только после подтверждения старого поведения. Библиотека не определяет KPI, не вмешивается в данные и не скрывает ошибки красивой отделкой.

## Дополнительные практики

К первоначальным восьми добавлены: иерархия действий и подтверждение опасной операции; один наиболее тяжёлый сигнал с раскрытием проверок; ноль против неизвестного; изменение единиц без изменения состава среза; длинные русские названия и область прокрутки; факт против предположения. В каталоге теперь 14 живых сценариев и 21 ссылка на действующие компоненты. Кодовые фрагменты **иллюстративны**, не самостоятельные файлы для копирования без интеграции с обработчиками и API.

## Архивные исходники вместо подменённого макета

В той же лаборатории вкладка «Исходные HTML» открывает все двенадцать доступных исходников Claude: семь основных макетов (pulse.html, zarya-vystavka.html, otdelki.html, ugol-varianty.html, ugol-otbora-krupno.html, ugol-v-linejke-demo.html, zarya-arheologiya.html), ранний palette-and-controls.html и три исходника 22.08 из docs/superpowers/audits. Двенадцатый — efir-uzel-schita.html — сохранён как **сырой фрагмент с кодом**, а не поддельная самостоятельная страница, поскольку у него нет собственной палитры/темы. HTML и его встроенная логика сохраняются, но iframe получает запрет внешних соединений, форм, переходов наружу и доступа к родительской странице. Отдельные фрагменты вроде efir-uzel-schita.html изучаются в реальном контексте оригиналов, не превращаются в самостоятельно оформленные страницы произвольным CSS.

Вид исходного HTML можно смотреть на 390, 768 и 1280 px; это ещё **не автоматическая визуальная регрессия** и не проверка совместимости с сегодняшним браузером при системном 200%. Сравнение проводится с действующим Header/OrgStrip/Report/Control, по сохранённым действиям, источникам, группам, периодам и состояниям. Иначе повторится известный класс брака из постмортема PR #92.

## Допуск к рекомендациям

- «Исходник» ≠ «рекомендовано» ≠ «принято владельцем» ≠ «внедрено».
- Кнопка учебного завершения не доказывает реальную запись; сигналы не дают KPI и штрафы за внешний вид.
- В прототипе нельзя заменять настоящую страницу и её API тремя строками демоданных, даже если тесты зелёные.
- Многолетние периоды, уведомления о чтении, разновидности организаций и два вида комментариев проверяются только реальным сквозным сценарием.
- В PR #88 нельзя расширять производственный store, БД или рабочие книги. Готовые компоненты остаются единственными владельцами поведения.

**Защита от противоречий:** учебные строки, суммы, адреса, комментарии и номера 173/1/173/2/174 задаются один раз в demo-data.ts. Палитры не подставляют собственную примерную закупочную арифметику. При изменении данных тесты сравнивают главную сцену, каталог практик и общий учебный итог.

Для всех 39 исходных пар лаборатория сохраняет цвет и исходное наименование; для пяти направлений показывает историческое отклонение и исправленные альтернативы. Все шесть отделок и семь визуальных состояний дают 1 638 комбинаций матрицы. Это число возможных комбинаций, НЕ количество визуально принятых или проверенных по пикселям элементов. Автотест контролирует отношения контраста исходных цветов; реальные текстуры, движение, стекло, полупрозрачность и наложение бликов требуют проверки отрендеренного состояния.

Заря должна жить ВНУТРИ выбранного предмета. Внешний голубой ореол возможен как слабый фокус/отклик, но не как основной смысловой носитель. Материал имеет физическую роль: стекло — слой навигации и барабанов, кэнди — один приоритетный выбранный контрол, металлик — малое механическое действие, перламутр — спокойный акцент, ксираллик — редкое подтверждённое событие, мат — длинные числа, таблицы, текст и ошибки. Опасное действие и предупреждение не перекрашиваются в тематический цвет небес.

### Pulse: большой круг — именно большая многомерная карточка

Источник требования: ../../specs/2026-08-22-pulse-brief.md, §4. Это требование повторялось до появления нынешней лаборатории. Текущий код:
- packages/web/src/pages/Dashboard.tsx, строки около 691–762: 2/3 ширины отдано столбцам исполнения, 1/3 — кругу.
- packages/web/src/components/charts/DrillPieChart.tsx, строки около 811–864: круг высотой 210 px, радиусы 58/85 px.
- docs/superpowers/audits/2026-08-20-cards-map/pult.md: предыдущая карта рисков и пользовательских взаимодействий.

Уже реализованные в эксперименте три варианта: текущий 210, крупный 330 и расширенный 380 px. Радиус зависит от доступного контейнера, чтобы на смартфоне круг не обрезался. Во всех вариантах сумма одной учебной базы — 13 620 тыс. ₽, раскрытие УО — 5 820 тыс. ₽; переключатель тыс./млн не меняет данные. Это не расчёты реального Dash.

Если владелец примет крупный вариант, начинать нужно с перестановки существующего DrillPieChart в более важную позицию Dashboard, а не с замены его новым демо-графиком. Сохранять четыре измерения: способ, бюджет, управление, исполнение; план/факт/экономию/количество; все источники и оговорки периодов, расхождения с итогом, скрытые отрицательные срезы, дробление по подведам, штриховки, явное применение глобального отбора и возврат по истории. Числовой список рядом с диаграммой обязателен для чтения без цветового различения.

### Атомарная карта реальных элементов — единственный поддерживаемый генератор

Канонический скрипт: packages/web/scripts/ui-atomic-atlas.mjs. Workflow: .github/workflows/dash-ui-atomic-atlas.yml. Он строит артефакт packages/web/artifacts/ui-atomic-atlas.json и человекочитаемую карту .md. Повторный запуск читает текущий код заново; руками копии JSON и таблицы данных не вести.

Проверенный исходниковый срез: 328 рабочих TS/TSX файлов, 201 тестовый файл исключён, 8 145 JSX-атомов, 709 событий/ссылок и 13 маршрутов. Файл каждой JSX-единицы, номер строки, окружающая функция, текст, aria, props, CSS-класс, импорт и вызывающая сторона указаны в JSON. Плюс цепочки Store-ключей и найденные статические/динамические API-адреса. Машинные цифры по маршрутам НЕ складывать: несколько страниц пользуются одними и теми же зависимостями.

Вкладка «Мастерская продукта» → «Атомы и связи» показывает 13 человекочитаемых контрактов: задачу пользователя, файл-владелец, существующие компоненты, критические действия, направление улучшений и прямые ссылки на реальный код и старый аудит. Примеры обязательной непрерывности:
- Pulse → Header, OrgStrip, период, функции фильтра, MDM, DrillPieChart, документы и возврат из детализации.
- Реестр / Не обеспеченные / В течение года → один DataBrowser, три разные роли, а не три самостоятельных источника.
- Мониторинг → отдельная процедурная книга, рубли, самостоятельные сроки и маршрут процедуры.
- Контроль → замечание, сигнал, рекомендация, доверие, результат, история и связи, без слепого объединения по названию.
- Всякая метрика → значение или причина неизвестности, источник, время, единица, период, формула и версия; ноль не равен отсутствию данных.

Это статический граф кода. Наличие у компонента JSX-prop не доказывает, что событие правильно выполнится или сохранится при отказе сервера. Не утверждать, что найденный через общий импорт API вызывается каждой страницей. Для принятия адресно проверять runtime на зафиксированном снимке, права пользователя, keyboard/focus, ошибки, пустоты, 390/768/1280, системное масштабирование 200% и rollback.
