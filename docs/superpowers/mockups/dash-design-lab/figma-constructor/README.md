# Dash — редактируемый конструктор Figma

**Назначение:** дополнить [существующий общий файл](https://www.figma.com/design/719aarL5EI0YEyqi6cRzgx), а не создавать новый макет, вторую лабораторию или замещать React. Источники — исходные HTML из PR #70, канонический каталог и атлас продукта в PR #83 → #88, 13 настоящих React-страниц и трёхрядный барабан PR #96.

**Статус:** исходный код и имитационное исполнение проверяются в GitHub CI. Сам запуск внутри Figma **не проверен**: квота MCP Starter в текущей сессии исчерпана. Исходный Figma-файл уже содержит три страницы, 117 переменных исходных цветовых пар, остальные переменные поверхности/геометрии, примеры 39 пар и 18 вариантов кнопок. Генерация 26 экранов в нём пока **не проводилась**, поскольку нет доступного Figma tool.

## Возможности конструктора

- 13 действительных разделов; пара «текущий» и «целевой» для каждого; 1440/1280/390 px; тёмное/светлое представление
- все 3 семейства из `zarya-vystavka.html` (без выдуманных цветов), 7 экспериментальных подложек, 6 отделок (мат, кэнди, металлик, перламутр, ксираллик, жидкое стекло)
- редактируемые стандартные Figma Frame, Text, Ellipse и Auto Layout — без растровых картинок, CDN, внешнего сервера и новых ГРБС
- существующие варианты не перезаписываются при повторном запуске: совпадение имени устойчиво в пределах выбранных параметров; ручные изменения сохраняются
- соблюдаются собственное оглавление `Report`, 5 разделов мониторинга, 6 контроля, 3 системы, 2 режима редактора реестров; исходные компоненты **не объявляются реализованными** в Figma
- включена попытка привязки выбранных цветовых предметов к уже существующим Figma Variables по имени организации/раздела, **не по номеру в массиве**

**Важно:** создаваемые Current — схемы функционального состава, а не покадровая/пиксельная копия React. Target — редактируемый вариант для обсуждения. Это *конструктор*, не автоматический 1:1 экспорт приложения; интерактив, бизнес-расчёты, Word, сервер и модели данных не переносятся магически в Figma.

## Как установить в тот же файл

Figma позволяет создавать и импортировать плагины для разработки в **настольном приложении на Mac/Windows**, а не в мобильном Safari. Инструкция: [Figma — создание плагина для разработки](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-plugin-for-development).

1. Получить папку `figma-constructor/` из [PR #88](https://github.com/gaben1488/dash/pull/88) с тремя файлами `manifest.json`, `code.js`, `ui.html`.
2. Открыть настольную Figma, меню **Plugins → Development → New Plugin**, выбрать Custom UI. Figma выдаст **собственный ID**.
3. В `manifest.json` этого каталога заменить учебный `id` на ID, созданный Figma, или перенести `code.js` и `ui.html` в созданный Figma проект, сохранив его Figma-сформированный manifest. Не использовать случайный ID другого плагина. Документация ID: [Figma Plugin Manifest](https://developers.figma.com/docs/plugins/manifest/).
4. Выбрать **Development → Import new plugin from manifest**, указать корректный `manifest.json`, либо запустить уже созданный New Plugin.
5. Открыть **тот же** [Dash Figma-файл](https://www.figma.com/design/719aarL5EI0YEyqi6cRzgx). В панели конструктора выбрать семейство, материал, подложку, текущий/целевой, размеры. Нажать «Добавить отсутствующие редактируемые экраны». Повторное нажатие не удаляет и не перестраивает прежние слои.
6. Для каждого изменённого элемента вручную выбрать роль, число, меру, ось, интерактивное состояние. Сравнить с **настоящим** React по тем же данным и размерам.

## Для разработчика

`node --check docs/superpowers/mockups/dash-design-lab/figma-constructor/code.js`

`node scripts/figma-constructor-qa.mjs`

Проверка использует имитацию базового Figma Plugin API, убеждается в построении 13×2 кадров, свойствах отчёта/контроля/мониторинга, мобильной компоновке, 6 образцах и отсутствии повторов при втором запуске. **Она не заменяет ручную визуальную проверку внутри Figma**.

## Ограничения тарифа и приёмка

- Тариф Starter ограничил исходный файл **тремя страницами**, поэтому каталоги сведены в три логические страницы. У коллекции только один mode, поэтому тёмные и светлые палитры заведены раздельно.
- Квота вызовов Figma MCP исчерпана; массовое создание фреймов из чата сейчас невозможно. Это конкретный блокер автоматического наполнения Figma, а не отсутствие исходников/генератора.
- Не переносить в рабочий `main` ни статичные прототипы, ни Figma-предложения без visual sign-off, совпадения на 1440/1280/1024/768/390, проверки 200% текста, клавиатуры, всех состояний и серверного контракта.
