# ДЭШ — расширяемая дизайн-лаборатория

**Состояние: экспериментальная реализация на отдельной ветке. Не production-изменение, не утверждённый редизайн.**  
Дата: 10.10.2026. Путь: dev-витрина `#/kit` → «Дизайн-лаборатория», либо `#/kit/lab`. Production не показывает и не загружает `Kit`/лабораторию: точка входа `packages/web/src/main.tsx` охраняется `import.meta.env.DEV`.

## Смысл и границы

Рабочий ДЭШ нельзя заменять красивой, но неполной демонстрацией. В репозитории уже есть `packages/web/src/pages/Kit.tsx` — существующая витрина **реальных** компонентов и редких состояний. Лаборатория — вложенная площадка исследования: увидеть исходные цвета, сравнить отделки/подложки, исследовать плотность и ошибочные состояния, сохранить или передать рецепт. Она ничего не записывает в рабочие Google Sheets, не вызывает закупочный API и не меняет Zustand/store приложения.

Это **не** перенос из `docs/superpowers/mockups/dash-consolidated/`, не замена `Header.tsx`, `OrgStrip.tsx`, `RowDetailCard.tsx`, реального реестра или исходного барабана. Прямоугольная демо-линейка в лаборатории — **цветовой стенд**, не навигационный макет для внедрения. При production-переносе брать геометрию/материалы из исходных HTML и существующего кода, а не из демонстрационных плиток. Пульс как содержательная страница в область переделки не входит.

## Что можно делать в лаборатории

1. Менять семейство, раздел, подложку, отделку, свет/ночь, плотность и режим движения в независимом preview.
2. Перебирать состояния *обычное / ожидание / ошибка / нет данных*, смотреть таблицу, изменять поисковый запрос и ведомство; видеть, что номер `173/1` остаётся `173/1`.
3. Открывать основу записи, различать увиденное, прочитанное и применённое обновление на учебной версии — без фактической записи.
4. Сравнивать два рецепта на одних и тех же вымышленных строках.
5. Сохранять наборы **только в локальном браузере**, экспортировать JSON и импортировать из JSON после строгой проверки полей, перечислений и версии.
6. Скопировать CSS-переменные текущего набора **только для `.dash-design-preview`**, чтобы использовать рецепт как материал для рассмотрения. Это не код миграции production.

Набор хранит **только оформление**, не закупочные строки: `{version,name,family,surface,finish,layout,section,mode,density,motion}`. Максимум 24 набора, не более 128 КБ на пакет, 32 КБ на один рецепт. Неизвестные версии, лишние поля, HTML/JS и необъявленные цвета отклоняются. Отказ `localStorage` не объявляется успешным сохранением.

Проверка контраста показывает минимум отношения текста к верхнему и нижнему цветам исходной пары. Она **не** удостоверяет автоматическую доступность любого блеска, смешивания, размера текста, тени, полупрозрачности и состояния.

## Карта кода

- `packages/web/src/pages/Kit.tsx` — существующий вход и кнопка лаборатории, только `DEV`.
- `packages/web/src/pages/DesignLab.tsx` — интерактивные стенды, сравнение, сохранение, объяснения.
- `packages/web/src/pages/design-lab.css` — изолированные стили сцены и физических проб, адаптивность, reduced motion.
- `packages/web/src/pages/design-lab/catalog.ts` — исходные палитры с зафиксированным происхождением и экспериментальные предложения.
- `packages/web/src/pages/design-lab/presets.ts` — схема рецептов, парсинг, хранение, CSS-экспорт, подсчёт контраста.
- `packages/web/src/pages/design-lab/presets.test.ts` — защита исходных палитр, читаемости, границ формата, хранения.

Ни один новый runtime dependency не установлен: используются уже имеющиеся React, Radix, lucide, Vitest. Детальная основа переноса из исторических HTML: [CONSOLIDATION-CONTRACT.md](https://github.com/gaben1488/dash/blob/codex/dash-design-stop-handoff-20261010/docs/superpowers/mockups/dash-consolidated/CONSOLIDATION-CONTRACT.md), [HTML-REVIEW.md](https://github.com/gaben1488/dash/blob/codex/dash-design-stop-handoff-20261010/docs/superpowers/audits/2026-10-10-dash-foundation/HTML-REVIEW.md) (в ветке PR #70, не на исходном main).

## Проверки и статус приёмки

Проверяемый минимальный набор:

```sh
pnpm -F @aemr/web exec vitest run src/pages/design-lab/presets.test.ts
pnpm lint
pnpm -r --workspace-concurrency=1 exec tsc --noEmit
pnpm -F @aemr/web build
pnpm -r test
```

Прямую проверку в этом окружении не объявляем зелёной до получения лога CI или фактического локального запуска. После открытия PR зафиксировать результат workflow отдельно. Недостаточно просто увидеть, что страница загрузилась.

**Для допуска в продукт необходимы отдельные гейты:** проверка исходного поведения барабанов и угла, корректности реальных фильтров и экспорта, визуальное сравнение с исходными HTML, WCAG контраст и фокус во всех реально применяемых комбинациях, keyboard/tab, screenreader, 200% zoom, ширины 390/768/1280, `prefers-reduced-motion`, отказы сервера, большие таблицы, производительность, историчность и версионность данных, затем согласование с владельцем. Демо-тесты не заменяют тесты всего Dash.

## Как продолжать без засорения и регрессий

Новые палитры — отдельными `EXPERIMENTAL_SURFACES`, а не заменой оригинального семейства. Новые варианты — с именем, задачей, объяснением роли, источником и честным статусом экспериментального. Поддерживать один формат пресетов с версионированием, сохранять старые рецепты при добавлении полей через явную миграцию; не вводить произвольный инжектируемый CSS. Реализованные в production компоненты развивать в своих файлах, при необходимости дополняя витрину `Kit`, но не переносить в неё демо-модель данных.

Следующий предметный цикл: покрыть визуальным тестом исходные HTML-навигацию/щит; вывести в лабораторию **настоящие** компоненты Button/Chip/Card и их состояния; добавить исполнение и проверки реальных сценариев поверх существующего store, не переписывая store. После оценки — отдельные адресные PR, а не крупный релиз «всё сразу».

## Ревизия: рабочая библиотека, оригиналы и устранение ложных успехов

Расширение PR #88 добавляет вкладку «Исходные HTML». Одиннадцать существующих самостоятельных HTML-макетов загружаются **по выбору** в изолированный iframe с ширинами 390/768/1280. Это подлинные файлы репозитория (встраивание добавляет лишь запрет сетевых запросов/форм); нельзя считать их утверждённым дизайном или достоверной предметной моделью. Страница «Пульс» используется только как источник общей оболочки и *не входит в предмет переделки*.

Первая версия после аудита исправлена: числа учебного среза зависят от фильтров; сравнение двух вариантов получает общий отбор и одинаковые исходные строки; основания выбранной строки разнесены на ячейку/значение/примечание/обсуждение; импорт, Undo и сохранение признают успешную запись только после факта записи; экспорт текущего оформления отличается от экспорта сохранённых наборов; поиск рецептов не оставляет справа невидимый старый рецепт. Добавлены автоматические тесты соответствующих действий.

Режимы реальных компонентов под локальной светлой темой **не все подтверждены**: класс темы рабочего Dash устанавливается на html, а Origin использует порталы за границей демонстрационного контейнера. Вместо ложного обещания 1:1 лаборатория явно предупреждает об ограничении и направляет к реальному Kit. Не применять экспериментальный CSS к production автоматически.

Крупные редизайны и изменение серверных расчётов в PR #88 не выполняются. Изменения реальных компонентов — только отдельным адресным шагом после подтверждения владельцем и защиты контракта.

Все 12 известных актуальных материалов Claude доступны из одного списка; источник `efir-uzel-schita.html` представлен как HTML-фрагмент исходного кода, а не как выдуманный самостоятельный экран. Удалённый `prototype.html` из коммита 22d35c0 — архив первоначальной идеи, не канон и не дополнительный современный макет.

## Мастерская продукта, история лазури и сквозная карта UI

Существующий вход остаётся прежним: разработческий адрес #/kit/lab. Дополнительная вкладка «Мастерская продукта» содержит четыре направления:
- **Лазурь и отделки.** Пять проверяемых направлений: архивные 7 и 14 августа, доступные пути восстановления и все три оригинальных семейства. Для каждого испытаны выбранное/покой/наведение/фокус/частично/запрет/ошибка и шесть видов отделки. 39 пар × 6 отделок × 7 состояний = 1 638 конфигураций для анализа, а не 1 638 доказанно красивых готовых рецептов.
- **Большой круг «Пульса».** Текущий маленький круг, крупный «герой», вариант углублённого просмотра. Сравниваются на одних фиктивных суммах, без замены настоящего DrillPieChart и всех его четырёх измерений/денежных режимов.
- **Механизмы.** Палитра команд Ctrl/⌘ K, причины ошибок, подтверждение чтения и сохранение фокуса; все кнопки учебные.
- **Атомы и связи.** Объяснимая карта 13 настоящих маршрутов, критических действий, исходных файлов и цепочек. Полный машинный граф строится из актуального React TypeScript, а не редактируется вручную.

Один источник данных для учебных чисел — demo-data.ts, а для инвентаря UI — packages/web/scripts/ui-atomic-atlas.mjs. Запуск карты:
1. pnpm install --frozen-lockfile
2. pnpm -F @aemr/web exec node scripts/ui-atomic-atlas.mjs
3. Открыть packages/web/artifacts/ui-atomic-atlas.md и ui-atomic-atlas.json либо последние артефакты workflow Dash UI atomic atlas.

История обнаруженного ухудшения цвета 7–14 августа, 39 свободных пар, связи с Apple HIG, Linear/GOV.UK/USWDS, роль материалов, ожидаемый большой круг и запреты на перенос содержатся в актуальном PATTERNS.md (раздел «Дополнительный предметный UX-ресерч»). Старая версия отчёта и исторический брак сохранены как provenance.

Тесты: общий CI monorepo, отдельных Vitest для мастерской, настоящий Chromium на ширинах 390/768/1280 px, скрипт атомов с реальными адресами. **Никакая часть этого стенда не делает production API-call и не меняет рабочие таблицы.** Снимки и успешный CI — доказательство DEV-функций на конкретном SHA, но не пользовательское утверждение любого нового дизайна.
