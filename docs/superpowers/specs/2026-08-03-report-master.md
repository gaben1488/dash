## §1. Мастер-промт (дистилляция всех запросов, по темам)

**Продукт.** Dash — доказательная BI по 44-ФЗ для 8 ГРБС Елизовского района.
Страница «Отчёт» и обе выгрузки = основной и дополнительный ручные отчёты
«версии ++»: то же самое, но лучше и больше по всем критериям. Дашборд
концептуально заменяет ручные отчёты: всё, что коллеги писали руками, видно
здесь — и больше. Пользуется «полный нуб» без обучения.

**Семь законов продукта (нарушение любого = регрессия):**

1. **До первички.** Каждое число, пункт, сигнал доводится до источника:
   книга → лист → строка → ячейка. Без ухода со страницы.
2. **БЗ везде.** Каждый показатель объясняется по наведению: что это, как
   считается (словами!), откуда, подводные камни. Тех-пути — провенанс в
   «Откуда», не в объяснении. Ни одного внутреннего ключа/латиницы/кальки
   в текстах UI (unmapped, uo, self, «КБ 2» — запрещены).
3. **Топ-N раскрывается.** Любой срез выборки разворачивается в полную
   выборку с поиском/фильтрами инлайн (ExpandableRows). Тексты не
   обрезаются троеточием.
4. **Эфир по умолчанию.** Живая картина сейчас; недельные срезы — архив.
   Сотрудник заходит в среду и видит, как аккумулируется неделя.
5. **Единый провенанс.** «Что изменилось» — одна лента, не две секции.
   Источник (журналы _ChangeLog до миграции / снимки после) — деталь
   реализации. Смена способа определения поставщика — всегда наверху.
6. **Текстовый дубль визуального.** Бар — с числом, цвет — с подписью,
   точка статуса — со словом.
7. **Честность.** Плашки вместо нулей без базы; происхождение чисел
   (расчёт/официал) всегда видно; расхождения периметров не молчат.

**Стиль работы:** целостные решения, не заплатки («находи первопричины и
решай ряд проблем во всём продукте»); шаг = коммит с зелёным гейтом;
короткие проверки, не часовые волны; ponytail — минимальный код, который
работает; менять «мало, но много где» — ощутимый результат за заход.

## §2.1. Методология сотрудницы (реверс эталона 26.06 по исходникам той же даты)

- **Числовые блоки** (план/факт/кварталы/деньги/исполнение по ГРБС): формулы
  СВОДа; воспроизведены знак в знак (week-regression, 3 недели).
- **«Расчётная экономия по оставшимся…»**: готовая ячейка яруса «Расч.
  экономия» СВОДа + разбивка бюджетов; в выгрузке живёт (parseSvodExtras),
  плашка — только без листа СВОД.
- **Перечни «осталось отыграть/заключить, в том числе»**: незаключённые
  строки квартала листа (гейт движка «нет даты факта», заглушка «Х» — тоже
  не заключено) + пояснение = «Комментарий ГРБСа» строки, литературно
  переписанный. Автоматизировано: pendingPositions + pendingNote.
- **Стадии («на стадии подачи заявок»)**: в листах колонки НЕТ — сотрудница
  берёт из ЕИС/личного учёта. Не автоматизируемо из текущих источников.
- **Адресные рекомендации** («предлагаем вынести на единый ЭА… позиция
  принята/не принята»): сырьё — пары колонок «Комментарий УЭР» (рекомендация)
  и «Комментарий ГРБСа» (ответ) построчно; сводные счётчики за историю —
  личный учёт. Построчные пары автоматизируемы (задача 16).

## §3. Приёмка «++» (когда отчёт готов)

- каждое утверждение обоих ручных отчётов есть на странице и в выгрузках;
- каждое число ведёт к ячейке; каждый показатель объясняется по наведению;
- все выборки раскрываются полностью; ничего не обрезано;
- провенанс: одна лента, повествовательные фразы, смена способа наверху;
- пояснения незаключённых видны и читаются;
- ни одного внутреннего ключа в UI; гейт зелёный; живая проверка в браузере.
