# Карта происхождения метрик: откуда берётся каждое число продукта

**Дата:** 18.08.2026 · **Основание:** канон п.104, директива владельца — «свод, отчет,
доп отчет, мониторинг, 44 фз — база нашей аналитики» · **Машинная карта:**
`packages/shared/src/metric-provenance.ts` (страж — `metric-provenance.test.ts`).

---

## 1. Зачем это

Продукт показывает без малого сотню чисел. Пока у каждого не назван источник, читатель
не может отличить число, взятое из официального листа, от числа, которое мы придумали
сами. Оба выглядят одинаково — цифра на плитке. Директива владельца закрывает этот
разрыв: у каждой метрики должна быть родословная из одного из пяти документов, а если
её нет — метрика обязана назвать себя нашей инициативой вслух, иначе она кандидат на
снятие.

Карта построена сверкой с живыми источниками, а не по памяти: дамп книги
СВОД_ДЛЯ_GOOGLE от 18.08.2026 (277 строк, 2 778 формул), дамп книги «Ежедневный
мониторинг» (14 листов), восемь выпусков еженедельного отчёта за 08.05–26.06.2026,
шаблонный выпуск 20.03.2026 с адресами ячеек в скобках и дополнительный отчёт
от 12.07.2026.

## 3. Источник 1 — лист «СВОД ТД-ПМ»

### 3.1 Что оказалось про устройство листа

Дамп показал то, чего карта имён в репозитории не знала: **лист состоит из девяти
одинаковых блоков по тридцать строк** — сводный «ВСЕ» и восемь управлений. Строки-якоря
блоков: 37 (УЭР), 67 (УИО), 97 (УАГЗО), 127 (УФБП), 157 (УД), 190 (УДТХ), 220 (УКСиМП),
250 (УО). Шапка повторяется в каждом. У «ВСЕ» и УД по шесть квартальных строк, у
остальных семи — по пять.

Внутри блока пять ярусов итогов, а не два: «Итого ЭА 2025+2026», «Итого ЭА 2026»,
«Итого ЕП 2025+2026», «Итого ЕП 2026» и сводные «КП+ЕП» / «ИТОГО 2026:». Продукт знает
только два последних.

### 3.2 Формулы листа — дословно

Все восемнадцать расчётных колонок сверены. Условие периметра `'ГРБС'!F:F = B$1`
(переключатель вида деятельности) стоит в каждой формуле листа.

| Колонка | Имя на листе | Формула листа |
|---|---|---|
| D | ПЛАН, единиц | `COUNTIFS(L≠"ЕП"; O=квартал; P=год; F=B$1)` |
| E | ФАКТ, единиц | то же + `Q≠"Х"; Q≠"X"; Q≠""` |
| F | Отклонение, единиц | `=E43-D43` |
| G | Заключено, % | `=IF(D43=0; "-"; E43/D43)` |
| H/I/J/K | ПЛАН ФБ/КБ/МБ/ИТОГО | `SUMIFS(H\|I\|J\|K; те же условия)` |
| L/M/N/O | ФАКТ ФБ/КБ/МБ/ИТОГО | `SUMIFS(V\|W\|X\|Y; + отсев по Q)` |
| P | Отклонение, тыс. руб | `=O43-K43` |
| Q | Законтрактовано, % | `=IF(K43=0; "-"; O43/K43)` |
| R/S/T | Экономия ФБ/КБ/МБ | `SUMIFS(Z\|AA\|AB; + AD="да"; + отсев по Q)` |
| U | Экономия ИТОГО | `=SUM(R43:T43)` |
| L2:O2 | Остаток к заключ. | `=H14-L14`, `=I14-M14`, `=J14-N14`, `=K14-O14` |
| G31/H31 | Доля ЭА, факт/план | `=O14/O29`, `=K14/K29` |
| G32/H32 | Доля ЕП, факт/план | `=O26/O29`, `=K26/K29` |

Отдельно стоит запомнить две вещи. Первая: лист отсеивает из факта обе буквы «Х» —
кириллическую и латинскую, — потому что операторы ставят их вместо пустоты. Вторая:
итог плана K лист читает как исходную колонку книги, а не как сумму трёх бюджетов, —
но только в блоках управлений; в сводном блоке и во всех строках итогов та же K уже
считается как `SUM(H:J)`. Лист сам себе не вполне верен, и наш запасной ход «пустой
итог — сложить три бюджета» воспроизводит вторую половину этой непоследовательности.

### 3.3 Сверка карты имён с живым листом

Файл `packages/shared/src/svod-sheet-names.ts`, созданный сегодня, выдержал проверку:
все восемнадцать адресов колонок D–U верны, имена совпадают дословно, включая свежие
переименования владельца («Заключено, %» и «Законтрактовано, %»), удаление строк
«Расч. экономия» подтверждено, значения переключателя B1 совпадают буквально. Мелких
поправок две: подпись A2 на листе длиннее (`* = ТД + ПМ ↑↑↑ ПЕРЕКЛЮЧАТЕЛЬ ↑↑↑`), а в
подписях D5/E5 внутри стоит перенос строки (`ПЛАН,\nединиц`) — сравнение имён «в лоб»
на них не сойдётся.

## 4. Источник 2 — еженедельный отчёт

Восемь выпусков подтвердили: структура постоянна. Шапка со ссылкой на СВОД онлайн,
сводный блок «ВСЕ ГРБС» с подразделами по конкурентным процедурам и по единственному
поставщику, затем восемь секций управлений в неизменном порядке. **Таблиц в
еженедельном отчёте нет ни одной** — это сплошная проза и маркированные списки; для
машинного разбора это значит, что делить документ нужно по формулировкам, а не по
стилям Word.

Показатели, которые отчёт печатает (формулировки дословные):

| Формулировка отчёта | Единицы | Есть у нас |
|---|---|---|
| «Всего на год запланировано N процедур на сумму X тыс. руб. (ФБ/КБ/МБ)» | шт + тыс. руб. | да |
| «Всего на 1 (2/3/4) квартал … запланировано N процедур на сумму X» | шт + тыс. руб. | да |
| «Фактически обязательства заключены по N процедурам на сумму X» | шт + тыс. руб. | да |
| «Общее исполнение плана 1 квартала – %» | % | да |
| «Отклонение от плана 2 квартала – N процедур» | шт | да, но со знаком листа наоборот |
| «- УО – 100,00% (план на 1 квартал – 55, исполнено 55, план на год – 150)» | % + 3 шт | да |
| «Остаток незаключенных договоров … до конца года – N» | шт | да |
| «В работе у отдела муниципальных закупок N процедур, в том числе по стадиям» | шт по 3 стадиям | **нет** |
| «Расчетная экономия по оставшимся незаключенным N процедурам – X тыс. руб.» | тыс. руб. | **нет** |
| «Даны N адресных рекомендаций; M приняты ГРБСами в работу» | шт | **нет** |
| «УКСиМП 81,68% от фактической суммы по ЕП (60% монополисты, 7% …)» | % | частично |
| «Из 2 374 процедур ЕП: 1 567 обоснованных, 807 выводимых» | шт | **нет** |
| «По итогу ЭА сумма НМЦК снижена на 24,68 %», «участвовали 5 поставщиков» | % + шт | **нет** |

Текстом отчёт делает три вещи: объясняет, почему процедура не отыграна в срок; фиксирует
вердикт управления по каждой рекомендации («Позиция принята УО при условии полного
финансирования», «Позиция не принята УО … высокая вероятность победы поставщиков
низкокачественного товара»); и копит аргументы о слабости контрактных управляющих
(«низкий уровень заинтересованности», «невысокая квалификация», «их трудозатраты кратно
превышают уровень заработной платы»). Причины задержек отчёт называет прямо: «Пакет
аукционной документации готов. Отсутствует финансирование», «не состоялся (подано 0
заявок)», «Дата планирования была указана ошибочно».

Побочная, но ценная находка: **шаблонный выпуск 20.03.2026 несёт после каждого числа
адрес ячейки** — «468 (D14) процедур на сумму 851 977,92 тыс. руб. (K14) (ФБ – … (H14))».
Это готовая карта соответствия «фраза отчёта → ячейка листа», и она совпадает
колонка-в-колонку с нашим парсером.

## 6. Источник 4 — книга «Ежедневный мониторинг» и главная находка

Книга оказалась не тем, чем её называет заголовок. **Сроков, стадий и просрочек она не
считает вообще.** Пять дат закупочного цикла — поступление заявки в уполномоченный
орган, публикация, окончание подачи заявок, проведение торгов, подведение итогов —
лежат в ней сырыми числами и только форматируются: ни одной формулы по датам, ни
сравнения с плановым сроком, ни классификации стадий. Поле «Статус» существует лишь в
двух скрытых пустых шаблонах. Это журнал ввода плюс арифметика экономии.

Весь её вычислительный аппарат — три формулы:

- `J3 =ROUND(D3-I3;3)` — экономия по процедуре: НМЦК минус цена аукциона, в рублях;
- `K3 =IF(SUM(L3:N3)=J3;"верно";"ошибка")` — контроль разложения экономии по бюджетам;
- `C4 =COUNTIF('1. УЭР'!I3:I1000;"<>"&"")` — счёт процедур по непустым ценам аукциона.

**Главная находка карты.** Лист «СВОДНЫЙ» этой книги имеет шапку «№ п/п · ГРБС · Общее
кол-во проведённых аукционов, шт. · НМЦК · Цена аукциона · Экономия ВСЕГО/МБ/КБ/ФБ».
Таблица дополнительного отчёта от 12.07 имеет шапку «№ п/п · ГРБС · Общее кол-во ЭА,
шт. · Экономия ВСЕГО/М.Б./К.Б./Ф.Б.». Это один и тот же документ. Значит, **57,7 млн
руб. экономии из отчёта руководителю — не та экономия, которую показывает продукт.**

В районе живут две экономии:

| | Экономия свода | Экономия мониторинга |
|---|---|---|
| Определение | утверждённая финансовым органом | НМЦК минус цена аукциона |
| Отбор | флаг AD = «да» в книге ГРБС | все состоявшиеся торги |
| Единицы | тысячи рублей | рубли с копейками |
| Где живёт | лист СВОД, колонки R–U | книга мониторинга, колонка J |
| Показывает ли продукт | да | нет |
| Кто читает | лист, сводная панель | руководитель района |

Продукт показывает первую и молчит про вторую. Руководитель, читающий и экран, и
записку, видит два разных числа под одним словом и не имеет способа понять, почему они
разные.

Побочно: в листе «СВОДНЫЙ» **разъехались правые границы диапазонов** при протяжке
формул — `F5` суммирует до строки 1001, `F6` до 1002, и так далее до `F11` (1007). Пока
данные кончаются около 110-й строки, итог верен, но формулы неоднородны и при росте
книги начнут врать по-разному в разных строках. Это дефект источника, о котором стоит
сказать владельцу книги.

## 7. Источник 5 — нормы 44-ФЗ

Закон обосновывает четыре метрики продукта: компонент доверия «соблюдение правил»
(ст.16, 21, 24, 93), счётчик закупок со снижением свыше четверти и одноимённый сигнал
(ст.37, антидемпинг) и сигнал «ЕП без обоснования» (ст.93). Пороги закодированы в
`LAW_44FZ_THRESHOLDS` и сверены с текстом закона: разовый лимит малой закупки 600 тыс.,
годовые альтернативы 2 млн либо 10 % СГОЗ с потолком 50 млн, для образования и культуры
5 млн либо 50 % СГОЗ с потолком 30 млн.

Оговорка, важная для честности: норма ст.37 считает снижение **от начальной
максимальной цены контракта**, а у нас в знаменателе плановый лимит — НМЦК в книгах
управлений просто нет. Порог законный, база приблизительная. Мост к настоящей НМЦК
существует: она есть в книге мониторинга. Он не построен.

## 8. Расхождения: десять мест, где наш счёт не равен счёту источника

| # | Метрика | Что считает источник | Что считаем мы | Цена ошибки |
|---|---|---|---|---|
| 1 | «Отклонение» (кол-во) | `F =E43-D43`, факт минус план: недобор отрицателен | план минус факт: недобор положителен | Вкладка «Свод» и панель показывают одно слово с разным знаком. Отчёт при этом на нашей стороне |
| 2 | «% исполнения» / «Законтрактовано, %» | одна колонка `Q =O/K` | две метрики с одной формулой и разными именами | дубль: два ключа, две записи в базе знаний, одно число |
| 3 | «Остаток к заключению» | `L2:O2 = H14-L14`, где строка 14 — **«Итого ЭА 2026»**: только конкурентные, только 2026 | та же арифметика к любой строке среза, включая КП+ЕП | при показе на КП+ЕП это уже не число листа |
| 4 | «Доля ЕП» | `G32 =O26/O29` — доля **по деньгам** | `ep_count / total_procedures` — доля **по штукам** | числа расходятся кратно: ЕП многочисленны и мелки |
| 5 | Периметр «все виды деятельности» | критерий `*` ловит любой непустой текст | наш срез «ВСЕ» берёт и пустые | строки с незаполненным видом деятельности у нас есть, у листа нет |
| 6 | Счёт процедур мониторинга | `COUNTIF` непустых цен аукциона | строки реестра по четырём стадиям | расходимся ровно на процедуры без цены |
| 7 | Среднее снижение на торгах | отношение сумм: Σэкономия / ΣНМЦК | среднее построчных процентов | отвечаем на другой вопрос — «как обычно снижается процедура», а не «на сколько подешевел портфель» |
| 8 | Снижение свыше 25 % | от НМЦК (ст.37) | от планового лимита | порог законный, база приближённая |
| 9 | Сигнал «снижение свыше 25 %» | то же | то же | подпись уже честная: «от лимита» |
| 10 | «Внесены под факт» | появление строки между снимками | состояние строки сейчас: факт есть, плана нет | пересекаются, но не тождественны |

Сверх этих десяти — **пятнадцать метрик в базе знаний подписаны неверными адресами
ячеек**, двумя разными способами.

Десять уходят за край листа. Колонки V/W/X/Y (факт) и Z/AA/AB/AC (экономия) принадлежат
листам управлений, а на своде те же величины живут в L/M/N/O и R/S/T/U. Лист
«СВОД ТД-ПМ» шириной ровно двадцать одна колонка, до U; ячейки «СВОД ТД-ПМ!V» не
существует вовсе. Затронуты `fact_fb`, `fact_kb`, `fact_mb`, `fact_total`, `economy_fb`,
`economy_kb`, `economy_mb`, `economy_total`, `total_economy`, `dept_fb_exec_pct`.

Ещё пять указывают на существующую колонку, но не на ту. `execution_pct` подписан
ячейкой H — это плановый федеральный бюджет, а не процент; `exec_count_pct` подписан
ячейкой E — это счёт заключённых, процент лежит в G; `comp_fact_count` и `ep_fact_count`
подписаны ячейкой G — она процент, а счёт в E; график `plan_fact_quarterly` подписан
ячейкой G, тогда как суммы лежат в H..O.

Верные адреса записаны в машинной карте, и страж теперь не даст вписать в неё колонку
за пределами A..U.

## 9. Метрики-сироты: двадцать три без документального источника

Сироты — не приговор. Треть из них закрывает реальную дыру, о которой источники молчат
именно потому, что бумага её не видит. Но каждая обязана назвать себя, и в машинной
карте у каждой теперь стоит обоснование.

**Оправданные — оставить, подпись уже есть.** Пять компонентов индекса доверия и сам
индекс: ни один документ не измеряет достоверность собственных данных, а отчёт
начальству опирается на числа, которых никто не проверял. Класс «не обеспечено
финансированием» (549 строк на 302 607 тыс. руб. в снимке 06.08): лист считает год
строго и такие строки не видит, отчего официальный лимит занижен — класс объясняет
системное расхождение, а не изобретает метрику. Класс «вид деятельности не указан»:
делает видимой ту часть строк, на которой наш периметр шире листового. Сигнал
«конфликт флага экономии»: молчащий флаг AD прячет экономию из свода, цена прямая.
Счётчики замечаний по управлениям — адресность, без которой замечание некому передать.

**Оправданные внешним методом — оставить, метод назван на карточке.** Четыре
экономические диагностики: декабрьский навес (метод — Liebman & Mahoney, American
Economic Review, 2017), точность планирования, разрыв исполнения между источниками
финансирования, соблюдение квартальной раскладки. Родословная у них научная, а не
документальная, и это честно сказано читателю.

**Кандидаты на снятие.**

| Метрика | Почему |
|---|---|
| `signal_stalled_contract` | детектор отключён 14.08 (канон п.27), всегда false, замечаний не создаёт — но занимает запись в базе знаний и подпись в интерфейсе |
| `trust_binary` | двоичный дубль общего индекса доверия |
| `dept_fb_exec_pct` | тройной дубль: одна дробь «факт ФБ / план ФБ» описана тремя записями (`fb_execution_pct`, `dept_fb_exec_pct`, `dept_fb_pct`), и только у последней верный адрес |
| `total_economy` | дубль `economy_total` на уровне района |
| `pending_count` | по построению равен `deviation`: строка либо имеет дату заключения, либо нет. Два ключа, одно число |
| `execution_pct` | равен `savings_pct` формулой; на листе колонка одна |
| `lifecycle_stage_unfunded` | читается как синоним «не обеспечено финансированием», различие признака (пустой год плана против нулевой суммы) читателю не видно |

## 11. План действий

### Первая очередь — правда о числах (дни)

1. **Починить адреса ячеек в базе знаний.** Пятнадцать записей ссылаются на колонки
   листов управлений как на колонки свода. Читатель, который пойдёт по адресу
   «СВОД ТД-ПМ!V», не найдёт ячейки: лист кончается на U. Страж в машинной карте уже
   стоит, осталось привести к нему `core/metrics/registry.ts`.
2. **Решить знак «Отклонения».** Сейчас вкладка «Свод» показывает сырое `E−D` листа, а
   панель — наше `D−E`. Рекомендация: оставить наш знак (он совпадает с отчётом и
   читается как «сколько недобрали»), но подписать на вкладке «Свод», что лист считает
   в другую сторону. Решение владельца обязательно — число смотрит начальство.
3. **Подписать периметр «Остатка к заключению».** На листе это только электронные
   аукционы и только 2026 год. Показ той же арифметики на КП+ЕП обязан говорить, что
   это уже наш пересчёт, а не число листа.
4. **Развести две экономии словами.** Утверждённая (лист, тысячи) и торговая (мониторинг,
   рубли) — разные величины. Пока показывается одна, подпись должна называть, какая
   именно, и упоминать вторую.

### Вторая очередь — снять дубли (дни)

5. Слить `execution_pct` и `savings_pct`: на листе колонка одна.
6. Слить тройку метрик исполнения федерального бюджета в одну.
7. Снять `signal_stalled_contract`, `trust_binary`, `total_economy` как отдельные записи.
8. Развести или слить `pending_count` и `deviation`, `lifecycle_stage_unfunded` и
   «не обеспечено финансированием» — с решением владельца по именам.

### Третья очередь — забрать то, что уже лежит (недели)

9. **Стадии процедур из книги мониторинга.** Еженедельный отчёт печатает их каждую
   неделю, книга даёт пять дат на процедуру. Это закрывает пробел, который держится в
   списке с июля.
10. **НМЦК и настоящее снижение** — из той же книги. Заодно превращает наш антидемпинговый
    сигнал из приближения в норму закона.
11. **Победители и концентрация поставщиков** — из колонки O книги мониторинга;
    детектор концентрации в ядре уже написан.
12. **Двухлетние итоги и ярусы «Итого ЭА 2026»** — парсер их читает, отчёт не использует.
13. **Контроль разложения экономии по бюджетам** — повторить формулу книги, это одна
    проверка целостности.

### Четвёртая очередь — вопросы владельцу

14. Методика **прогнозной экономии** по незаключённым: строки «Расч. экономия» с листа
    удалены, а отчёт эту цифру печатает. Откуда она теперь берётся?
15. Знак «Отклонения» (см. п.2) — какое поведение считать правильным.
16. Имена классов «не обеспечено финансированием» и «без плановых денег» — оставить два
    или свести к одному.
17. Дефект источника: разъехавшиеся диапазоны в листе «СВОДНЫЙ» книги мониторинга.
18. Написание сокращений управлений расходится между книгами: «УАГЗО» и «УДТХ» в своде
    против «УАГиЗО» и «УДТХиРКИ» в мониторинге, «УАГиЗО» в таблице допотчёта. Нужен один
    словарь.

## 12. Как карта живёт дальше

Машинная карта `packages/shared/src/metric-provenance.ts` держит родословную 86 метрик.
Страж `metric-provenance.test.ts` проверяет шесть правил: каждая метрика словаря продукта
имеет запись; источник — один из шести известных; описание счёта источника не пустое;
наша инициатива обоснована; расхождение названо; адрес на своде не выходит за колонку U.
Отдельным блоком тест фиксирует найденные расхождения — чтобы никто не «починил» знак
отклонения или периметр остатка, не поговорив с владельцем.

Порядок при добавлении новой метрики теперь такой: сначала назвать источник и то, как
считает он, потом писать расчёт. Метрика, которая не может назвать источник, называет
себя нашей инициативой и объясняет, зачем она нужна. Третьего варианта страж не
пропускает.
