Каждый найденный дефект — не «почини строку», а «найди весь класс и закрой везде».
Доказательство необходимости: за эту волну поштучно закрыты три экземпляра ОДНОГО

## ТРЕК B — Сквозная консолидация дублей (НОВЫЙ, системный)

Одноразовый СВЕП всего кода: найти ВСЕ экземпляры класса «несколько реализаций
одного» и свести к единому канону. Не по одному при встрече — разом, реестром.

Кандидаты-семьи (подтвердить свепом, не по памяти):
- **парсинг дат** (parseDate × сколько? signals/recalculate/calc-engine/web-форматтеры);
- **резолв листа/источника** (readDeptSheet теперь канон — все ли через него?);
- **классификация листа** (classifySheet — единственная точка?);
- **нормализация ключей латиница↔кириллица ГРБС** (сколько мест?);
- **форматирование денег/процентов** (web: сколько разных toLocaleString-обёрток?);
- **чтение колонок по буквам** (buildCellDict / прямые индексы — единый ли доступ?);
- **гейт «есть факт»** (hasFactDate / has-fact — один предикат?);
- **человеческие лейблы** (productLabel — единственный путь, или ещё есть карты?).

Выход трека: реестр `docs/.../consolidation-sweep.md` (класс | экземпляры file:line |
канон | план слияния), затем слияние с тестами. Это исполняется **фан-аутом**
(агент на семью), не вручную по очереди.

## ТРЕК C — Продукт: модуль совмещения (уточнён пользователем 14.07, ДВА УРОВНЯ)

Ключевое уточнение: совмещение — не одна фича, а два уровня.

**Уровень 1 — организационные рекомендации к совмещению** (как аналитик даёт 143
рекомендации): «эти разрозненные закупки объединить в единый ЭА», «заменить ЕП на
ЭА». Выход — предложения человеку, с обоснованием и прогнозом экономии. Трекинг
исходов (принято/отложено/нецелесообразно/ГРБС-сменил) — в БД реакций dash.

**Уровень 2 — работа с данными (унификация):**
- (а) **свод мета-контекста**: новеллы / объяснения / оправдания ГРБС (столбец AE и
  пр. свободный текст) → унифицированный контролируемый словарь причин/статусов
  (не свободный текст, а нормализованные категории + исходный текст рядом);
- (б) **свод названий закупок к справочнику**: СВОЙ справочник номенклатуры, НЕ
  ОКПД2/ОКВЭД/КТРУ. Причина (со слов пользователя): в ЕИС коды часто не совпадают
  с тем, что реально покупают. Значит нормализуем по фактическому названию
  (лемматизация + кластеризация похожих), а коды ЕИС — вспомогательный сигнал, не
  основа. Это и питает Уровень 1 (похожие названия → кандидат на объединение).

**СТАТУС КОДА (verified инвентаризацией 14.07, не по памяти) — почти всё УЖЕ ЕСТЬ, не выведено:**
