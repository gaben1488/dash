# Работа с документацией Dash

Общие правила, ветка, приоритет решений и выбор проверок — в корневом
[AGENTS.md](../AGENTS.md). Этот файл уточняет только работу с `docs/`.
Прежний workflow июня с обязательным новым worktree и rebase на main
не применяется к действующему интегратору. Изолировать чужой WIP необходимо;
параллельные агенты и новые ветки не запускаются автоматически.

- Найти существующий документ по [карте](../README.md#documentation-map).
  Задачи и стадия — только [PLAN](PLAN.md#current-execution); не создавать
  новый план, «финальную» сводку или независимый список остатка.
- Отличать принятое требование, предложение, реализацию и датированное
  доказательство. У аудита указывать исследованные SHA/источники/ограничения;
  его старые измерения не называть актуальными. Историю и исходные ID сохранять.
- Менять правило в его предметном доме и ставить ссылку из точки входа.
  Не копировать команду, статус выпуска или длинный канон в AGENTS/CLAUDE/README.
  Позднее решение сопровождается основанием, а не просто новой датой.
- При консолидации точных дублей оставить исходный текст по одному адресу,
  а старый адрес сохранить указателем. Сохранить используемые якоря и ссылки;
  не удалять разделы только за давность или большой объём.
- Для Markdown проверить diff, локальные ссылки/якоря, сохранность ID и
  требований. Если документ генерируется, править источник генерации.
  Примеры/команды с побочными эффектами должны явно называть среду и допуск.
- `.mulch/` — tracked канал экспертизы, если утилита настроена. Старые уже
  tracked файлы `.claude/` — исторические источники; это не разрешение добавлять
  новую локальную память, private reports, дампы или базы. Они остаются вне Git.

Текстовая правка не подтверждает установку, live-readback или бизнес-приёмку.
Не обходить hooks и не запускать production/запись в Sheets ради проверки MD.
