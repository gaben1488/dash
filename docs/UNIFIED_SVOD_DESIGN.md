# Единая структура «СВОД» — дизайн (2026-06-05)

> Статус: **approved** (пользователь, 2026-06-05). Источник истины для реализации
> ядро→UI. Заменяет раздельные «СВОД ТД-ПМ» (Q1/Год) и «ШДЮ/СВОД с месяцами»
> (месяцы) одной сверенной сеткой.

## 1. Проблема и инсайт

В книге `СВОД_ДЛЯ_GOOGLE` три листа считают одно и то же по-разному:

| Лист | Период | Активность | Роль |
|---|---|---|---|
| `СВОД ТД-ПМ` (279×24) | Q1 + Год | X37=`*` (ТД+ПМ, см. X38 «* = ТД + ПМ») | официальные ячейки, панель |
| `СВОД с месяцами` (558×41) | 12 мес + Q1-Q4 | AN4 ∈ `*`/`ТД`/`ПМ` (статика под Apps Script) | помесячный срез |
| `ШДЮ старый` (516×25, legacy) | мес | — | устаревший, заменяется |

**Инсайт:** это **одна логическая сетка** `ГРБС × метод(КП/ЕП) × бюджет(ФБ/КБ/МБ) ×
{кол-во, план, факт, экономия}`, различается лишь **гранулярностью периода** и
**активностью**. Объединяем в одну.

## 2. Решение: CalcEngine = истина, листы = сверка

**Источник истины — CalcEngine, считающий из атомов** (dept-строки, 33 колонки),
а НЕ формулы листов. Причина: формулы листов содержат реальные баги (УАГЗО/УФБП
ссылаются на чужой лист — найдено reconcile), листы одноактивностны (один AN4) и
статичны (Apps Script). Атомы прослеживаемы и полны. Это «железобетон».

**Листы — слой доверия (cross-check), не источник.** Для каждой ячейки единой
сетки, где есть лист-эталон (СВОД ТД-ПМ для ВСЕ×{Q1,Год}; СВОД с месяцами для
текущего-AN4×{мес,кв}), показываем «✓ сверено» или «⚠ расхождение N% + причина».
Снимает вопрос «какой лист источник» (никакой — атомы) и одноактивностность.

## 3. Атом → сетка (маппинг dept-столбцов)

Dept-лист, строка-атом, 0-based для парсера:

| Столбец | Поле | Назначение |
|---|---|---|
| B (1) | dept | ГРБС |
| C (2) | subordinate | подвед |
| **D (3)** | **program** | **Наименование программы — «графа программы»** |
| **F (5)** | **activity** | `Программное мероприятие` / `Текущая деятельность` |
| **L (11)** | **method** | `ЭА…`→КП / `ЕП`→ЕП |
| O (14) / P (15) | planQuarter / planYear | период плана |
| N (13) | planDate | дата плана (→ месяц) |
| Q (16) | factStatus | дата факта; `Х`=нет факта |
| R (17) / S (18) | factQuarter / factYear | период факта |
| H/I/J/K (7-10) | plan FB/KB/MB/ИТОГО | план-суммы |
| V/W/X/Y (21-24) | fact FB/KB/MB/ИТОГО | факт-суммы |
| Z/AA/AB/AC (25-28) | economy FB/KB/MB/ИТОГО | экономия |
| AD (29) | economyGate | `да`/`нет` — учитывать экономию |

## 4. Ось активности (4 среза)

| Срез | Правило (по атому) |
|---|---|
| **ВСЕ** | любая строка (= ТД+ПМ, как X37/AN4=`*`) |
| **ПМ** | `F = 'Программное мероприятие'` |
| **ТД** | `F = 'Текущая деятельность'` |
| **ТД-ПМ** | `F = 'Текущая деятельность'` И `D ∉ {X, Х, x, х, '', пусто}` (ТД с программой) |

ТД-ПМ ⊂ ТД (под-разбивка). `activity-scope.ts` расширяется: scope `all|pm|td|td_pm`.

## 5. Ось периода

Единая: `месяц(1-12) | квартал(Q1-Q4) | год`. CalcEngine считает все; листы сверяют
свои (СВОД ТД-ПМ: Q1+Год; СВОД с месяцами: мес+кв). Месяц атома — из N (план) / Q (факт).

## 6. Метод / бюджет / ГРБС

Метод: КП(ЭА и аналоги) / ЕП (столбец L). Бюджет: ФБ/КБ/МБ/ИТОГО — реальный фильтр
(суммы по выбранным бюджетам, количества не делятся). ГРБС: 8 + сводный ВСЕ.

## 7. Инварианты сверки («железобетон»)

1. `ВСЕ = ПМ + ТД` (по кол-ву и суммам, любой период/метод/бюджет).
2. `Год = Σ(мес 1-12) = Σ(Q1-Q4)` в CalcEngine.
3. `CalcEngine[ВСЕ, Q1/Год] ≈ СВОД ТД-ПМ` (расхождение → флаг + причина).
4. `CalcEngine[AN4-срез, мес/кв] ≈ СВОД с месяцами` (если AN4 листа известен).
5. Экономия учитывается только при `AD='да'` (как лист).
Каждый инвариант → тест.

## 8. UI

Вместо двух таблиц — **одна** (переиспользует существующие табличные компоненты
`SvodTableHead`/`BlockGroup` с цветокодом План/Факт/Экономия). Фильтры:
активность(4) · период(мес/кв/год) · метод · бюджет · ГРБС. Колонка-индикатор
«сверено ✓ / ⚠ расхождение (причина)». Блок «причины расхождений» под таблицей.

## 9. Слои реализации (скилл на слой)

1. **shared контракты:** `activity-scope.ts` (+td_pm), типы единой сетки `UnifiedSvodGrid`.
2. **core:** CalcEngine группировка `активность×метод×бюджет×период` из атомов
   (TDD: `test-driven-development`); reconcile cross-check vs оба листа; инварианты §7.
3. **server:** API единой сетки + сверка в snapshot.
4. **web/UI:** одна таблица + фильтры (`impeccable-shape`→`impeccable-polish`).
5. **verify:** `verification-before-completion` (gates + invariants + live).
6. **deploy:** VPS.

## Анти-цели (YAGNI)

- НЕ читаем 3 AN4-среза листа через write+read (статика Apps Script — бесполезно).
- НЕ делаем сетку источником листы (одноактивностны + баги).
- НЕ вводим новые периоды кроме мес/кв/год.
