# Контракт интерфейса и непрерывности пользовательского пути

**Статус:** proposed distillation; не утверждённый редизайн.

## Не менять смысл ради оболочки

Сначала документируй исходный HTML/существующий интерфейс и все маршруты: щит, барабан периода, угол фильтров, вкладки, комментарии, фильтры, возвраты, состояния, экспорт и историю. Изолированные лабораторные макеты — эксперимент, не автоматически approved design. Существующий «Пульс» менять только при прямо указанной области.

## Проверяемая метрика-карточка

- Показатель имеет понятную задачу человека, определение, единицы, официальный/расчётный режим, дату источника, применённый scope, недоступные оси и объяснение.
- Все карточки, таблицы, графики и переходы одной сцены используют **один фактически применённый отбор**. На пустом выборе не рисовать прежнее число или 0 из пустого источника.
- Drill-down возвращает к тем же атомам; сохраняет учреждение, ГРБС, способ, период, бюджет, вид деятельности, когда оси поддержаны. Если ось неприменима — явная пометка, не тишина.
- Сигнал имеет один дом с типом и действием: `source_error`, `data_quality`, `probable_risk`, `observation`, `owner_recommendation`. Синонимы без полного равенства множеств строк не объединять.
- Русские подписи, без внутренних ID, `UNMAPPED`, англоязычного жаргона или необоснованных юридических «нарушений».

## Исторические проверенные ошибки — обязательные негативные тесты

1. Фильтр менял таблицу, но не заголовки/итоги; тестировать каждую применимую ось.
2. Прототип экономии по plan−fact; не переносить демо-арифметику в core.
3. Номер `173/1` мог быть свёрнут в `173`; проверять не только надпись, но и идентичность/дедупликацию.
4. Библиотека потеряла Undo после failed persist; тестировать отказ localStorage и server 409/503.
5. Перейти от ГРБС к учреждению без чужих сигналов; проверить общее состояние selector и nav state.
6. Контраст локальной светлой карточки при глобальной тёмной теме, реальные Popover/Portal, EmptyState; проверять взаимодействие, не только скриншот статичного компонента.
7. Слишком длинные русские названия и 320/390/768/1280 px, обе темы, zoom 200%, keyboard, reduced motion.

## Порядок принятия

Функциональная матрица до/после → subject calculation fixture → UI-тесты → реальный браузер с исходным HTML и данными → owner acceptance. Эстетическая оценка отдельна от механической; зелёные тесты не доказывают принятия цветов или геометрии.
