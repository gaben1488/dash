# Миграция справочника заказчиков — история решений и приёмки

**Актуализация 11.10.2026.** Ниже сохраняется протокол предварительного тестирования ДО массовой миграции. Восемь действующих план-реестров и рабочие процедуры впоследствии были мигрированы (приоритет R, иначе E); повторять это действие не требуется и запрещено. Последующая независимая read-only сверка, уже сохранённая в `docs/superpowers/audits/2026-10-10-live-subordinate-duplicates.md`, установила 85 уникальных ID центрального справочника, 680 идентичных локальных записей в восьми книгах, 4 093 рабочих строки и ноль нераспознанных именованных значений C. Изменений первичных закупочных сумм на этапе совместимости Dash нет: исходники не редактируются. Исторические имена читаются по проверенным алиасам без замены исходной подписи снимка. CI Dash не доказывает работоспособность отдельного отчётного worker; проверка схемы процедур с 34 столбцами и эксплуатационный допуск остаются за PR #90 / issue #93.

## 11.10.2026 — миграция отображаемых имён вкладок (исполнено частично)

Владелец уточнил: помимо заполненных значений B/C, требуется привести **имена вкладок организаций** к действующему справочнику. Ранее данный пункт был пропущен. Для минимизации риска применены только изменения `updateSheetProperties(fields=title)` с сохранением `sheetId`; первичные ячейки, формулы, список листов и статусы скрытости не изменялись. Центральный «Справочник заказчиков» (85 записей, R→E) — источник имени, `AG` используется для короткого названия собственно управления, не подменяя юридические поля B/C.

Read-only preflight проверял каждую зеркальную вкладку по прямому `FILTER('ВСЕ'!... = '_Настройки'!Hn)`, затем уникальность значения `Hn` в центральном каталоге. В УО эта проверка дала 47/47, в УКСиМП — 22/22 привязок, включая аппарат с `Х/X`. Для аппарата УКСиМП имя вкладки взято из проверенного `AG=УКСиМП`; отметка `Х/X` не превращалась в учреждение. Разделены «Совместные закупки (УО)» и «Совместные закупки (УКСиМП)»: группы не являются самостоятельным юридическим лицом и не объединяются.

Образцы: `Опека → УО (Опека)`; `Администрирование → УО (Администрирование)`; `ЦДТ → МБУДО "ЦДТ"`; `МКУ «ЦБО и МТО» → МКУ ЦБОИМТО`; `Совместная закупка → Совместные закупки (УКСиМП)`. Технические и агрегирующие листы `ВСЕ`, `СИСТЕМА`, `_Настройки`, `_ChangeLog` сохраняют название. Для восстановления точных старых названий есть история ревизий Google Sheets, в т. ч. зафиксированные revision IDs УО `109638` до изменений и `109643` после, УКСиМП `27396` до и `27397` после. Не откатывать всю книгу из истории вместо адресного возврата имени по `sheetId`, если за это время были другие правки.

**Не выполнять пока:** переименование **основных источников** `УФБП`, `УДТХ`, `УИО` и иных листов, которые Dash/генератор читают по *имени*, пока не расширены и не приняты точные source-contract/alias-fallback, исторические снимки и Apps Script. Для УФБП рабочее сокращение справочника `AG=УФ`, для УДТХ `AG=УДТХиБ`; точные имена R имеют до 108–112 символов и не помещаются в Google Sheets (лимит 100). Простая массовая замена сейчас создаст очередной производственный отказ. `УО`, `УД` и `УЭР` как вкладки аппарата уже соответствуют рабочим сокращениям, переименование не нужно.

**Недоказанное:** источники Apps Script и установленные триггеры здесь недоступны; проверка записи в `_ChangeLog`, уведомлений, всех формульных/динамических ссылок и readback каждого потребителя целиком ещё не закрыта. Не считать приведённые счётчики полным release PASS. Существующий #79 и issue #69 — общие точки координации, отдельных конкурирующих документов/листов не создавать.

## Предварительный этап (историческое состояние до миграции)

Статус на момент этой предварительной проверки: **перенос ещё не был принят**. Здесь зафиксированы только результаты фактического чтения Google Sheets и проверенных исправлений. Этот документ не подтверждает готовность всей миграции.

## Канон идентичности

- Основной лист `Справочник заказчиков` реестра процедур: 85 заполненных записей / 85 уникальных UUID в колонке S; пустых UUID среди записей нет.
- Общая группа `Совместные закупки (УО)` уже заведена под № 85 (физическая строка 86) с устойчивым UUID; не является юридическим лицом и не получает фиктивный ИНН.
- Из 85 записей: 77 со статусом «Действующий», 6 групп заказчиков, 2 со статусом «Ликвидирован». Исторические и ликвидированные записи нельзя удалять ради текущих фильтров.
- Тестовый справочник процедур: те же 85 ID без повторов; тестовый локальный справочник УО: 59 ID без повторов, все ID и ID управлений-родителей присутствуют в основном справочнике.
- Приоритет отображаемого имени, фактически используемый тестовой схемой: столбец R (если заполнен) → E. Восемь значений R у управлений являются длинными названиями, несмотря на подпись «сокращённое». Рабочие аббревиатуры в AG тестового справочника — отдельное поле и не должны подменять юридическое имя.

## Исправления, уже применённые

1. **Тестовый реестр процедур.** В формулах контроля `Рабочий реестр процедур!Y3:Y1002` устранена зависимость от неверных относительных смещений именованного диапазона `КанонЗаказчиков`: чтение управления привязано к `'Справочник заказчиков'!$C$2:$C$500`, чтение алиасов — к `$I$2:$I$500`. После переноса канонического диапазона на AH старый `OFFSET` читал чужие столбцы и создавал массовые ложные замечания.
2. **Тестовый контроль процедур.** Исторические ожидаемые названия управления в 14 строках `_Проверки!C142:C148` и `C534:C540`, плюс `E597`, заменены формулами разрешения имени по UUID. Проверка не принимает необоснованно новое имя из произвольного текста.
3. **Основной справочник процедур.** Из `I3:I5` удалён исключительно неоднозначный алиас «Совместные закупки» (его первоначальное наличие в каждой из трёх строк задокументировано здесь). Все остальные алиасы сохранены; общая форма остаётся на записи №85. Проверено повторным чтением.
4. **Восемь действующих план-реестров и рабочие строки основного реестра процедур** в ходе описанного прогона массово не изменялись.

Подведомственные листы УО — FILTER-зеркала, а не самостоятельные источники, поэтому их нельзя мигрировать повторным заполнением поверх формул.

## Не пройдено, требуется до переноса в production

- **Критический UX/целостность:** B/C в тесте УО и E/F в тесте процедур одновременно формулы `ID→имя` и выпадающие поля ручного выбора. Выбор сотрудником нового имени перезаписывает формулу. До внедрения нужно спроектировать устойчивую транзакцию ввода: сохраняется ID, отображаемое имя выводится из ID; без «технического UUID» в человеческом интерфейсе.
- **Отсутствует единая live-синхронизация:** `_Справочник` в тесте УО — физическая копия; изменения основного справочника сами по себе туда не поступают. Не считать эту копию единственным источником истины.
- Не проверены массово референсы, валидаторы, именованные диапазоны, фильтры, аналитика, интеграция Dash и формульные/денежные регрессии **всех восьми** действующих план-реестров.
- Переименования листов по названию организации потенциально меняют ссылки у скриптов/интеграций. Sheet ID должен оставаться стабильным; меняется только отображение, когда все потребители готовы.
- Уникальный ID отделять от юридических реквизитов. Не объединять однофамильные и омонимичные учреждения автоматически; для совместной закупки ID группы не является ID юридического лица.
- Перед релизом необходимы сравнение до/после (строки, деньги, формулы, сигналы, фильтры), проверка ручного ввода/переименования, ревизионный барьер против одновременных правок и откат.

## Следующий безопасный этап

Доработать в одной изолированной тестовой книге редактирование `организация → ID → отображаемое имя` так, чтобы штатное изменение через список сохраняло ID и не разрушало формулу. Затем воспроизвести контрольные случаи (обычная организация, подвед, аппарат, совместные закупки, переименование, исключённая/ликвидированная организация, одноимённые алиасы), сверить агрегаты и связи Dash и только после успешного гейта делать **поочерёдный** перенос в восемь live-книг с чтением после каждого шага.
