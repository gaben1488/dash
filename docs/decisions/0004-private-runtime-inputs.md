# Закрытые входы производственного генератора

Исходные матрицы, реестр рекомендаций и реальные идентификаторы источников не
публикуются в Git и журналах Actions. Ключ сервисного аккаунта уже находится в
среде сервера; переносить его в чат или новую систему секретов не требуется.

Однократное подключение использует закрытый JSON в Google Drive с точным именем
`aemr-report-runtime-inputs-v1.json`, доступный существующему сервисному аккаунту
только на чтение. Поиск обязан вернуть ровно один файл подходящего типа. Ноль,
два файла, неполная выдача или изменение версии во время чтения дают отказ.
Архивы и похожие имена не перебираются. Содержимое проверяется по контракту.

Пара registry/ledger записывается во временный каталог на постоянном томе,
синхронизируется и становится доступной через одно переименование. Существующие
входы автоматически не перезаписываются. Последующая миграция схемы должна быть
явной, с новым проверенным контрактом; ежедневный ручной контекст не нужен.

Развёртывание сначала подключает входы и запускает полный выпуск существующим
сервисным аккаунтом. Вывод сохраняется только в закрытом томе сервера. Периодический
worker включается лишь после успешного запуска. Сбой сохраняет предыдущий выпуск.
Частные данные и вывод предметных проверок не попадают в публичный журнал CI.
