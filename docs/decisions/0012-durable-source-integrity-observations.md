# ADR 0012 — долговременные результаты контроля источников

**Статус:** proposed, 2026-10-22. **Проект:** Monitoring Dash, текущая SQLite БД сервера.

## Контекст

Снимки, книга/ревизия и `book_watermarks` уже переживают рестарт; три результата контроля — доставка формул, разбор формул и дозор настроек — пока живут лишь в `Map` процесса. После перезапуска `/api/sources/integrity` теряет сведения до следующего webhook либо ночного обхода. Повторный ночной запрос или принудительное массовое чтение при каждом старте не решает проблему и расходует Google API.

## Решение

1. **Одна дополнительная компактная SQLite-таблица `source_integrity_state`.** По одному JSON-документу на пару (вид проверки, книга); только вердикты, замечания, время, количество ячеек, ошибки доставки. **Не** дублировать 98 тысяч формул, значения строк, недельные архивы или отпечатки книг.
2. Для формул хранить **атомарно** последний результат попытки доставки и последний успешно разобранный вердикт. Новая неуспешная попытка должна оставаться видимой, не подменяться старым успехом; предыдущий подтверждённый вердикт сохраняется с оригинальным временем. Для метаданных также атомарно хранить последнюю попытку (включая отказ Google) **и** последнее подтверждённое наблюдение с прежним временем; никогда не выдавать старую проверку за результат последней попытки.
3. В документ включать вид проверки, версию контракта/канона и идентификатор источника. При смене канона или замене исходной книги прежний результат исключать из актуальных проверок, без миграции пользовательских таблиц и без автоматической выдачи «чисто».
4. При `createApp` восстановить состояния из БД **до** запуска фоновых обходов и webhook-обработчиков. RAM остаётся быстрым пересоздаваемым представлением. При отказе записи явно отмечать `persisted:false`, выводить предупреждение и не считать проверку завершённой. Сама выдача таблиц продолжает работать.
5. `GET /api/sources/integrity` показывает времена и границу знания; `POST .../check` засчитывает только доставки/вердикты **этого** запуска и достоверное сохранение, не прежние данные с диска.
6. Оставить webhook-first, экономный плановый опрос и ночную страховку пропущенных событий. **Не** вводить новую ночную «реанимацию» RAM, новые Google-опросы после рестарта, второй механизм снимков или поля в исходных Google-книгах.

## Гейты приёмки

- RED/GREEN тест: успешная проверка → имитация рестарта → восстановлены время, дефекты и число ячеек без запросов к Google.
- Новая неуспешная проверка переживает рестарт; последнее успешное заключение не маскирует отказ.
- Подмена `spreadsheetId`, повреждённый JSON, смена версии канона и ошибка SQLite трактуются fail-closed.
- `ddl.test.ts` подтверждает схему на пустой БД; `pnpm -r tsc --noEmit && pnpm -r test` и CI exact-head.
- Production gate отдельно: backup SQLite, deploy на VPS, readback `/api/sources/integrity`, повторный рестарт и readback на той же версии, проверка после webhook, rollback. До этого этап **не** считать закрытым.

## Несделанное намеренно

Не объединять контроль с PR #102, консолидацией сигналов и UI-дизайном; не изменять значения Google Sheets, поведение недельных архивов, CalcEngine и формулы правил условного форматирования.
### Совместимость интегрированной ветки

Изменения накладываются на `codex/dash-audit-integrated-20261010` без слияния устаревшего `main`. Сохраняются проверки составных номеров закупок, фиксация source-cut, цепочка report worker и исходный UI. Версия формульного анализатора обновлена до `formula-integrity/2-integrated-composite`; результаты, записанные отдельным legacy-релизом, не признаются текущей проверкой. Внедрение — только отдельный принятый выпуск из интегрированного контура; автоматически переносить результат CI legacy-ветки запрещено.
