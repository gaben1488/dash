# ADR-0014: полная база источников и инкрементальная актуализация

Статус: инженерный кандидат для C05.04 и R05.02, без production-приёмки.
Текущий источник кода: интегратор Dash PR #79. Номер 14 в согласованном
списке из 20 — C05.04, а не C08.14 (последний — отдельный пилот СУБД).

## Инварианты

1. Полный первичный состав обязательных master-книг, их геометрия, значения,
   формулы и необходимые листы официальной сводной книги образуют единый
   подтверждённый source manifest. Отсутствующая книга не становится нулём.
2. Локальная БД хранит предыдущую принятую полную базу и её идентификаторы,
   подписи, отметку времени и версию правил. При сбое чтения эта база остаётся
   нетронутой. Старый read-model можно показать только со старой датой и
   признаком stale, не как новое измерение.
3. Вебхук — сигнал об изменении файла, не полноценная поставка данных.
   Успешная актуализация накладывает на полную базу результат чтения
   затронутого источника. Хранимый снимок не может состоять из новой части
   источников и произвольно исчезнувших остальных.
4. В пределах одного цикла не принимается смесь удачного и неудачного
   чтения. При ошибке книги, ревизии, обязательного СВОДа или сохранения
   новый bundle не публикуется; очередь повторяет непринятое событие.
   История и прежние опубликованные Word остаются неизменными.
5. Для публикации модели обязательны полное sourceCoverage, полный
   sourceReceipt и успешные наблюдения. Попытка составить модель без них —
   отказ, а не «успех с неполным покрытием».
6. Показанное отсутствие изменений — только результат сверки. Неизвестная
   ревизия, ошибка API, нечитавшийся источник и пустой ответ — разные
   состояния; им запрещено становиться «0 изменений».
7. Экономия обеспечивается сопоставлением версии и выборочным чтением
   изменившегося файла. Остальные master-книги не перечитываются. Сравнение
   старого и нового полных состояний затронутой книги даёт diff.

## Ограничения Google Drive

Стандартный Drive push webhook не содержит changed A1 range, row number
или cell address. Поэтому текущая доказуемая гранулярность внешнего чтения —
изменившаяся КНИГА. Система вычисляет её diff локально после чтения.
Это не является «скачиванием только изменившихся ячеек».

Переход к реальному range-level delta допустим только при надёжном журнале
всех типов изменений с монотонным курсором и независимой проверкой
полноты: значения, формулы, вставки/удаления строк, API-изменения,
пересчёт зависимостей, schema changes и разрывы доставок. При пропущенном
курcоре или непроверяемом диапазоне — полная сверка затронутого файла.
Один _ChangeLog, основанный на onEdit, не гарантирует всю эту полноту.

## Исполнение и приёмка

Патч сохраняет последнюю полную базу при сбое webhook-группы, блокирует
неполную новую материализацию и отделяет stale от fresh. Адресные тесты
фиксируют отсутствие смешанного commit и защиту старых источников.

Для закрытия C05.04 как эксплуатации нужны exact-head CI, read-only
доказательства полного источникового состава, независимая сверка KPI/Word,
восстановление после обрыва событий, измерение cold/warm/worker p95 и
контролируемая приёмка на VPS. Состояния Google Sheets не изменяются
этим PR. Работа с range-level delivery относится к отдельному
источниковому контракту и не может быть ложно объявлена готовой.
