# Устойчивые идентификаторы справочника

Решение: отдельный технический UUID в S («ID учреждения») справочника заказчиков. UUID сохраняется с записью при переименовании и перестановке; адрес ячейки остаётся только адресом доказательства. Группы совместных заказчиков получают такой же технический ID, без выдуманного ИНН. Пустой, неверный или повторный UUID диагностируется; по нему нельзя объединять записи. Новые записи получают ID при обновлении справочника. Существующие ID не перезаписываются. Никакие диапазоны не защищаются.

Сопоставление существующих написаний по алиасам сохраняется. Добавление ID не подтверждает юридические реквизиты и не разрешает спорные совпадения.


## Общие справочники и представление — 21.10.2026

Идентичность не равна подписи: стабильный ключ и точное имя исходного листа
сохраняются при переименовании. Действующее имя и все подтверждённые исторические
написания управлений принадлежат department-registry.ts. Реестр ГРБС — совместимое
представление этих данных; собственный набор алиасов в нём запрещён. Нормализация
ввода, фильтры, мониторинг и подписи продукта используют один resolver findDept.
Незнакомое имя сохраняется, нечёткое объединение не выполняется.

Названия метрик и экранные словари принадлежат shared/product-dictionary.ts.
Движок и БЗ берут подпись по ключу; формулы и источники остаются в своих
существующих предметных реестрах. Экранные словари сгруппированы по контексту:
одинаковый технический ключ разных сущностей не означает одинакового смысла.
Формат квартала и справочник месяцев общие. Исторические цитаты, названия
исходных вкладок и адреса доказательств не переписываются ради нового имени.

Содержание БЗ метрик (registry, kb-uplift и типы) также перенесено в shared/metrics.
Прежние экспорты core сохраняются как совместимые ссылки на тот же объект;
копии записей не создаются. Проверки публичных экспортов остаются на прежнем
контракте, перенос охраняют TypeScript и ESLint.

Общий межъязыковой носитель управлений —
packages/report-engine/src/procurement_engine/department_directory.json. TypeScript
импортирует тот же файл; Python включает его как package-data. department-registry.ts
и department_directory.py — адаптеры, не копии справочника. JSON содержит действующие
имена, стабильные ID, точные привязки мониторинга, подтверждённые алиасы и разрешённые
переименования исходных вкладок с неизменными book ID/sheet ID. В web-образ копируется
только этот файл данных. Распознавание по фрагментам названия удалено из Python:
неизвестное имя не присваивается похожему управлению.

Уникальные реальные написания закреплены независимой проверкой Python. Нормализация
NFKC, пробелов, регистра и Ё/Е одинакова в обоих адаптерах; конфликт алиаса даёт явный отказ.
