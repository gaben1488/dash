# DASH — проверяемые примеры дистилляции старых MD

**Статус: предложенная редакция, НЕ замена первичного контракта без PR.** Каждый пример сопоставляет контекст, ошибочное обобщение, новый краткий пункт и тест; это не гарантирует, что исходная производственная проблема остаётся открытой сегодня.

## Пример 1. Старая карта D/E → инвариант схемы

**Источники:** `docs/METRICS_CONTRACT.md` (ранняя схема), `docs/decisions/0007-source-context-and-document-content-contract.md` и реально прочитанный `packages/shared/src/column-map.ts@c4b792a`.

**Исторический риск:** несовместимый смысл программы/предмета и потеря последних комментариев AF/AG/AH из-за частичной парсинг-карты.

**Дистиллят, scope `packages/shared/**`, `packages/server/**`:** «На чтении master распознай актуальные заголовки A:AH; D=программа, E=подпрограмма, F=вид, G=предмет, AF/AG/AH=полевые комментарии; несовпадение схемы не исправляй эвристическим сдвигом». **Проверить:** fixture на 34 колонки и повторное чтение настоящих заголовков. **Статус:** mapping подтверждён текущим кодом, актуальные live книги нуждаются в отдельной проверке.

## Пример 2. «Экономия» как декоративная KPI → предметный гейт

**Источники:** `docs/METRICS_CONTRACT.md`, `docs/decisions/2026-10-08-monitoring-money-attribution.md`, `docs/superpowers/audits/2026-10-10-design-library-postmortem.md`.

**Ошибка:** демо-экономию обозначили `план−факт`, хотя это отклонение; настоящая учтённая экономия зависит от Z/AA/AB, Q и AD. **Дистиллят:** «Разводи отклонение и экономию разными metric ID; экономию master считаем только при корректном Q и AD=да. Доля участника + остаток = исходная сумма, НМЦК и победитель — отдельные сущности». **Проверить:** AD=`нет`, Q пуст, корректные и некорректные доли, знак отклонения. **Статус:** правило предложено из действующих контрактов, требуют тесты на каждом используемом расчётном доме.

## Пример 3. Пилот справочника → безопасное правило распространения

**Источник:** `docs/decisions/2026-10-10-customer-directory-migration-qa.md`.

**Контекст:** 85 UUID в справочнике и пилотные проверки сработали; однако массовое внедрение в восемь masters прямо не принято. **Ловушка:** перенести слово «готово» без ограничения scope; выпадающий ввод имени способен уничтожить формулу `ID→имя`.

**Дистиллят:** «Группы совместных закупок не юридические лица; ID хранится отдельно от отображения; не мигрировать восемь production masters до подтверждения edit round trip и независимого readback каждой книги». **Проверить:** dropdown не уничтожает formula, идентичность сохраняется при переименовании/ликвидации, rollback. **Статус:** частичный пилот; не выдавать за принятый rollout.

## Пример 4. Временная историческая топология → только dated observation

**Источник:** `docs/TECHNICAL_SHEETS_COMPATIBILITY_2026-10-10.md`.

**Контекст:** сам документ сначала описывает `Settings/Контроль/_Справочник` как сохранённые, а в заключении 11.10 сообщает об их физическом удалении из восьми master-книг; Apps Script не перенастроен.

**Дистиллят:** «Перед правкой техлиста/триггера построить граф зависимостей book/sheet/formula/script/webhook/changelog; после изменения проверить реальную доставку и запрещать `green` по одной только валидации ячеек». **Проверить:** отсутствующий sheet + `onEdit` + readback `_ChangeLog`. **Дата источника:** 11.10; сегодняшняя топология отдельно unknown до свежего metadata readback.

## Пример 5. Новая концепция SQLite → proposed, не обязанность runtime

**Источник:** `docs/decisions/0012-durable-source-integrity-observations.md` (прямо `proposed`, 22.10).

**Контекст:** предлагается сохранять результаты доставок/проверок схем в SQLite, показывать последнюю попытку отдельно от последнего доказанного вердикта, не повторять массовые Google-вызовы при каждом старте.

**Дистиллят:** «Внести в backlog-кандидат малую persisted integrity state с ключом `(kind,source,contract_version)`, отдельными timestamps и явным `persisted:false` при ошибке». **Не делать:** переписывать первичные 98 тысяч формул, объявлять feature уже внедрённой. **Проверить после принятия:** restart + failed attempt + corrupt JSON + смена source ID + реальный VPS readback.

## Пример 6. Неудачная дизайн-библиотека → проверяемый UX контракт

**Источник:** `docs/superpowers/audits/2026-10-10-design-library-postmortem.md`.

**Контекст:** фильтруемая таблица и статичная карточка; сравнительные preview с разными данными; строка `173/2` показывала соседнюю причину; save мог окончиться ложным успехом при отказе localStorage.

**Дистиллят:** «Одна атомарная выборка данных и selected ID управляют таблицей, KPI, объяснением и drilldown; ошибки persistence не закрывают Undo; восстановить theme context для portaled UI». **Проверить:** 3 соседние строки, пустая выборка, темы, отказ записи. **Статус:** исторические дефекты исходных demo-PR — не утверждение о текущей production.

## Вывод

Хорошая MD-инструкция **не** переносит целую историю эксперимента. Она оставляет в рабочем контексте краткое условие → действие → проверку и ссылку на полный исходник. История, дата, фактическая степень доказанности и обратимые решения живут в отдельном слое.
