# DASH — проверка агентных правил и документальный gate

**Только документация.** Положительный результат теста MD не доказывает исправление кода, файлов Google, данных, worker или production.

| Проверка | Негативный сценарий | Что признаётся доказательством |
|---|---|---|
| Хронология | `1.10` как дата; тестовая закупка `15.03.2023` как дата решения | Поле `date_role`, явный источник timestamp; неразрешённое → unknown |
| Устаревшие решения | 2d «оставить два канона» после 3d «слить» | `supersedes=2d`, активен лишь поздний вариант; старое сохранено |
| Версионность | У старого по имени августовского файла новое решение 23.10 | Git blob SHA/коммит + история блока, а не путь-имя |
| Статусы | «СДЕЛАНО» от 21.08 объявили нынешним DONE | `verified_on` и gate; старое получает `historical` |
| Дублирующие инструкции | Два «главных» плана и два независимых AGENTS/CLAUDE процесса | один active canonical home; ссылки, no concurrent rules |
| Колонки | D описательная графа, E программа; пустой AH → row skipped | test against `column-map.ts`, 34 slots and sparse row, header fingerprint |
| Неполный source | одна из восьми книг не прочитана, watermark сдвинулся | старый accepted baseline и receipt неизменны, `stale/partial` явный |
| Деньги | `plan-fact` автоматически назван экономией; NMCk названа лимитом | formulas and GRBS/method scope, independent reconciliation |
| Время | нет прошлой контрольной даты → пропало 0 | explicit no-baseline state, Kamchatka time, stated window |
| UI | фильтр ГРБС выбран, но при клике таб изменил выбор | same FilterContext -> cards/grid/CSV, cross-mode test |
| Отчёт | worker упал в середине второй итерации и удалил старый DOCX | previous accepted artifacts intact, reproducible run, restore/rollback |
| Приватность | черновой owner transcript или credentials в Git | linter/content audit, redacted repo-only package |

Отдельно нужен **review двумя агентными средами**: пусть каждая выполнит 6 одинаковых заданий (метрика, источник, snapshot failure, UI-filter, report-worker, исторический статус), сравнить correctness и число неуместных прочитанных документов. Проверка должна падать на специально возвращённом неправильном старом правиле и успешно проходить после замены. Пока этот A/B-run **не выполнялся**.

**Стоп-критерий:** модификация инструкции, увеличивающая число правил или обязательных чтений без предотвращённого зарегистрированного дефекта, отклоняется. Новые правила добавляются после воспроизведения настоящей ошибки и с тестом; устаревшие убираются с `superseded_by`.
