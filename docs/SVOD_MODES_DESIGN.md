# Два режима СВОД + детализация по ГРБС — направление дизайна

> Статус: **направление (WIP, pre-spec)**, 2026-06-05. Следующая фаза goal+плана.
> Дизайн до кода (brainstorming → impeccable-shape → writing-plans). Не реализовывать
> до утверждённого дизайна.

## Решение (зафиксировано с пользователем)

Не пресеты одной сетки, а **два разных продукта на одном движке + сверка**. Каждый
режим — живой двойник своего исходного листа: раскладка, цвета, расположение ячеек,
поведение по годам различаются «почти во всём».

### Режим A — «СВОД ТД-ПМ»
- Выглядит и ведёт себя как лист **СВОД ТД-ПМ** (279×24): раскладка/цвета/ячейки листа.
- Период: квартал + год (Q1, Год — как офиц. лист). Разрез ТД/ПМ на виду.
- Данные считает CalcEngine из атомов, сверка с листом ТД-ПМ (как сейчас, Δ 0.00%).
- TODO канон: местами ещё захардкожен 2025 — привести к выбранному году.

### Режим B — «СВОД с месяцами»
- Выглядит и ведёт себя как лист **СВОД с месяцами** (558×41): его раскладка/цвета/ячейки.
- Переключашка по годам, работает **строго в рамках одного года**.
- Период: 12 месяцев + кварталы. Помесячная динамика.
- Сверка — с листом «СВОД с месяцами» (текущий AN4-срез).

### Часть 2 — детализация по ГРБС (слагаемые)
- Раскрыть управление на **«само управление»** (закупки самого ГРБС) + его **подведы**.
- Показывать слагаемые только для управлений, у которых ≥1 подвед.
- Интуитивно, красиво: раскрытие/панель/drill-in — выбрать в дизайне.

### Часть 3 — починить «само управление» (org-itself)
- Сейчас концепт размазан по **13 файлам** (`recalculate`, `calc-engine`, `validate`,
  `subordinate-registry`, `types`, `Economy`, `Dashboard`, `OrgStrip`,
  `useMultiDimMetrics`, …) → «неоднородно и хреново».
- Та же болезнь «разрозненного определения», что и column-map/amountDeviation.
- Лечить консолидацией: один канон «само управление = строки с пустым/самоссылочным
  столбцом C», единый helper, все потребители через него + регресс-тесты.

## Подход к дизайну (следующая фаза)

1. **Знать оба листа холодно.** `xlsx_style_extract.py` по обоим табам (заливки, шрифты,
   merge, number-format, геометрия блоков) + визуальный осмотр живого листа. Сверить с
   `report-map.ts` (ТД-ПМ) и `shdyu-map.ts` (месяцы).
2. **Диагноз «само управления».** Прочитать 13 файлов, выписать расхождения org-itself,
   определить канон.
3. **2-3 продуктовых варианта** компоновки двух режимов + drill-down → выбрать с пользователем.
4. **impeccable-shape** (UX-макет до кода) → дизайн-док → writing-plans → реализация
   ядро→UI с сверкой и тестами на каждом слое.
