# AEMR Agent Notes

Этот файл содержит только проверяемые правила работы с репозиторием. Внешние vault/memory ссылки не являются частью проекта.

## Canonical Commands

```bash
pnpm lint
pnpm typecheck
pnpm -r test
pnpm build
pnpm audit --audit-level moderate
```

Перед заявлением "готово" нужно выполнить релевантный набор команд и явно назвать результат.

## Project Facts

- Monorepo: `shared`, `core`, `server`, `web`.
- Runtime server: Fastify, Node 22, TypeScript ESM.
- Runtime web: React 19 + Vite 6.
- Current database implementation: SQLite through `better-sqlite3` and Drizzle schema.
- Production deploy: `deploy/docker-compose.yml`, not root-level Docker files.
- Production auth: `AEMR_API_KEY` is required; `/api/health` is public; other `/api/*` routes require `Authorization: Bearer <key>`.
- Google Sheets IDs are configured in code defaults and can be overridden through env/config; credentials must never be committed.

## Editing Rules

- Do not commit generated build info: `*.tsbuildinfo`.
- Do not put secrets, service account JSON, SQLite DB files, reports, graph outputs, or local agent artifacts into git.
  - Единственное исключение, разрешённое владельцем 29.07.2026: выжимки недель
    `packages/core/src/report/__fixtures__/week-*.json` для регресса «расчёт против ручного
    отчёта». Проверены: плановые строки закупок, без ключей и персональных данных. Новые
    фикстуры того же вида добавлять можно; любые другие отчёты в git по-прежнему нельзя.
- Keep documentation factual. If a command, route, script, deploy path, or table is not present in the repo, do not document it as implemented.
- Prefer `@aemr/shared` constants and `@aemr/core` calculations over duplicating legal/procurement thresholds in UI or server code.
- Keep `docs/REVIEW.md` updated when security posture or verification commands change.
- **МАНДАТ ВЕДЕНИЯ ПРОЕКТА — `docs/superpowers/specs/2026-08-22-mandate.md`.**
  Читается ПЕРВЫМ, перед любой работой. Главное в нём: инцидент — это всегда
  КЛАСС дефектов, а не случай (локализация → формулировка класса → перепись
  всех носителей → матрица покрытия → правка класса → страж → канон);
  работа сделана не когда закоммичено, а когда владелец увидел на проде;
  план показывается ДО правки; свежий дамп всегда; о гибели агента сообщает
  исполнитель. Язык всех артефактов — русский, без единого английского слова
  в интерфейсе и базе знаний.
- Живая матрица корректности метрик — `docs/superpowers/audits/2026-08-22-metrics-matrix.md`.
  Единственное место, где видно, что закрыто, а что нет. Не переписка.
- Определение готовности карточки — `docs/superpowers/specs/2026-08-21-card-done-definition.md`
  (канон пп. 53, 58, 104, 119, 127, 129, 131, 132, 135, 139). Любая работа над
  экраном читает этот список ДО начала и предъявляется по нему. Частично
  выполненный список не считается: карточка либо доведена, либо нет.
- Атлас продукта `docs/superpowers/audits/2026-08-20-cards-map/` — живой артефакт
  (требование владельца 20.08.2026): любая волна, меняющая UI вкладки, обязана
  обновить карту этой вкладки (инвентарь карточек, источники цифр до файла:строки,
  навигация и интерактив, вердикты по канону). Карта, разошедшаяся с кодом, хуже
  отсутствующей — при правке экрана без обновления карты волна не считается завершённой.

## Обязательные уроки UI-провалов (10.10.2026)

Прежде чем проектировать или оценивать оболочку Dash, дизайн-библиотеку, новую карточку или переиспользуемый компонент: читать [документированный отказ от прежнего макета в PR #70](https://github.com/gaben1488/dash/blob/f338af5a827841dd2eecf5086bbf7f257c222d8b/docs/superpowers/audits/2026-10-10-dash-stop/README.md) и [постмортем лаборатории #83/#88](docs/superpowers/audits/2026-10-10-design-library-postmortem.md). В дополнение к мандату 22.08 и готовности карточки — правила ниже, не новые конкурирующие «каноны».

- **Нельзя повторять отклонённый дизайн:** заменять оригинальные барабаны, щит, угол и OrgStrip стандартной сеткой/боковой панелью без явного выбора владельца; игнорировать изначальные HTML Claude; подменять консолидацию очередным «по мотивам». Источник-основа — реальный код и сохранившиеся файлы, не первый красивый скриншот.
- **Нельзя принимать макет по зелёному CI:** запуск React и тесты фиктивных записей подтверждают только проверенное ими. «Технически собран» / «источники учтены» / «визуально принят» / «сохранены рабочие сценарии» / «на проде увидел владелец» — разные статусы. Не писать final/ready/PASS без соответствующего доказательства.
- **Демонстрация обязана быть честна внутри себя:** при фильтрации меняются и таблица, и подписи, и числовые итоги; в сравнении вариантов один зафиксированный набор строк и одинаковые отборы; карточка показывает основание именно выбранной строки; «формула, примечание, обсуждение раздельно» — только если есть три отдельные видимые сущности.
- **Действительные компоненты проверяются целиком:** токены темы должны влиять на кнопки, подсказки, Popover/Portal, ошибочные состояния и EmptyState, а не только на нарисованную карточку. Для code snippet статус «готово» разрешён лишь при реальном тесте компиляции и работы; иначе писать «иллюстративный фрагмент». Недоопределённые CSS-переменные не считать полноценной палитрой.
- **Контракты важнее полировки:** каждую новую систему UI сопоставить с задачей человека → действующей функцией/данными/API → исходным HTML → экраном → состояниями → сохранёнными действиями. Защитить прежние выгрузки, периодики, фильтры, историю, черновики, подведов, два вида комментариев и доказательства чисел. Исключение содержимого «Пульса» не исключает его общую оболочку.
- **Код макета не определяет предметные расчёты:** исторический неудачный прототип складывал экономию как план минус факт, что противоречит обязательному AD-gate. Фиктивные проценты, рейтинги и статусы — не нормативный или бизнес-контракт. Никаких переносов из демонстраций в @aemr/core.
- **Не повторять семантическую слепоту макетов:** показ номера 173/1 не доказывает отсутствия ложных дублей в ядре; два учебных ГРБС не тестируют согласование подведов (прецедент #74: 22 лишних пункта), отказ сохранения не означает успех (#75/#78/#79), а единый переключатель не делает каждую ось фильтра применимой к каждому разделу. Эти случаи принадлежат сквозным приёмочным матрицам, не косметическим тестам.
- **Эксперимент не равен утверждённому:** «Космос», «Камчатка», «Минералы» — сохранённые альтернативы; новые поверхности и имитации отделок — предложенные варианты. Даже выбор по умолчанию в DEV Kit не является согласием владельца. Существующую рабочую страницу не заменять цветовым стендом.

Проверяемые дефекты лаборатории на оценённом SHA и действия — в постмортеме. Этот раздел обязателен и для Claude, и для Codex; не скрывать известные дефекты за фразой «все тесты зелёные».
