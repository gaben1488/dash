# Деплой dash на Render (бесплатно, публичный просмотр для начальства)

> Динамический dash (живые данные из Google-таблиц) на бесплатном хостинге.
> Один сервис отдаёт и API, и интерфейс. Режим **только для чтения** — просмотр
> открыт всем по ссылке, изменение данных отключено (защита исходных таблиц).

## Почему Render, а не Vercel

Vercel — статика + короткоживущие функции; наш сервер постоянный, с `better-sqlite3`
(нативный модуль) и снапшотом в памяти — на Vercel не живёт без переписывания в serverless
(недели). Render free гоняет обычный долгоживущий Node + Docker и уже подходит без переделок.

## Что уже готово в репозитории

- `Dockerfile` (корень) — сборка web (SPA → `public/`); сервер+shared+core запускаются из
  исходников через `tsx` (см. «Рантайм-заметка» ниже), SPA отдаётся `fastifyStatic`.
- `render.yaml` (корень) — Blueprint: free web-сервис, Docker, healthcheck `/api/health`.
- `AEMR_PUBLIC_READONLY=true` — публичный режим только для чтения
  (`packages/server/src/middleware/auth.ts`): ключ не нужен, GET открыты, запись → 403.
- Порт/хост Render-совместимы (`env.PORT`, `HOST=0.0.0.0`).

## Ограничения бесплатного tier (сказать начальнице)

1. **Засыпает через 15 мин простоя.** Первый заход после паузы — холодный старт (~30-60 с) +
   загрузка 9 таблиц и прогон пайплайна. Первая загрузка может быть 1-2 минуты, дальше быстро.
2. **Эфемерный диск.** Локальная SQLite (снапшоты/история) сбрасывается при рестарте —
   для просмотра неважно: дашборд пересобирается из Google-таблиц на старте.
3. **Только чтение.** Правки (редактор ячеек, статусы) вернут 403 — это защита, а не баг.

## Шаги (5-10 минут; делаете вы — нужен ваш аккаунт)

1. Ветку с этим коммитом влить в `main` (Render проще цепляется к main), либо на шаге 4
   выбрать текущую ветку `claude/refactor-consolidation`.
2. Завести аккаунт на https://render.com (можно через GitHub-логин, карта не нужна для free).
3. **New → Blueprint** → подключить репозиторий `gaben1488/dash`. Render найдёт `render.yaml`
   и предложит создать сервис `aemr-dash`. (Либо **New → Web Service** → тот же репо →
   Runtime: Docker → Dockerfile Path: `./Dockerfile` → Plan: Free.)
4. Выбрать ветку (`main` или `claude/refactor-consolidation`).
5. **Environment** — задать переменные для РЕАЛЬНЫХ данных (иначе покажет демо):
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL` — email сервис-аккаунта Google.
   - `GOOGLE_PRIVATE_KEY` — приватный ключ сервис-аккаунта (многострочный; вставить как есть,
     переносы строк Render сохранит; сервер сам заменит `\n`).
   - `GOOGLE_SHEETS_SPREADSHEET_ID` — id таблицы СВОД (если отличается от дефолта в коде).
   - `NODE_ENV=production` и `AEMR_PUBLIC_READONLY=true` уже в `render.yaml`.
   > Сервис-аккаунт JSON НИКОГДА не коммитить в git — только в Render UI (secret env).
   > Сервис-аккаунту дать доступ (просмотр) к 9 таблицам, как на текущем VPS.
6. **Create / Deploy.** Первая сборка Docker — ~5-10 мин. Логи видны в Render.
7. Готовый URL вида `https://aemr-dash.onrender.com` — отправить начальнице. `/api/health`
   должен отвечать `{"status":"ok"}`.

## Проверка после деплоя

- Открыть URL → дашборд грузится (первый раз медленно — cold start + пайплайн).
- `GET https://<url>/api/health` → `ok`.
- Попытка записи (в UI «сохранить» в редакторе) → 403 «только для просмотра» — как задумано.

## Обновление данных

Данные тянутся из Google-таблиц при старте/refresh. Правки в таблицах видны после
перезапуска сервиса (Render → Manual Deploy → Restart) либо истечения кэша (5 мин, если
сервис не спал). Автообновления по расписанию на free-tier нет.

## Если нужен приватный доступ позже

Free-tier Render не даёт встроенную защиту паролем. Варианты на будущее: Render paid
(password protection), Cloudflare Access перед сервисом, либо полноценный RBAC (фаза 7
мастер-плана — роли УЭР/ЦЭР/ГРБС-вьюер). Пока — публичный просмотр (данные 44-ФЗ и так
публичны на zakupki.gov.ru).

## Рантайм-заметка (важно для сборки)

`@aemr/shared` и `@aemr/core` — исходные TS-пакеты (`main` = `src/index.ts`, в dist не
собираются). Поэтому сервер запускается **через tsx из исходников** (`packages/server` уже
держит `tsx` в зависимостях + скрипт `start:prod`), а НЕ `node dist/index.js` — последнее не
резолвит workspace-алиасы в рантайме (tsc их не переписывает). Dockerfile это учитывает:
hoisted node_modules + исходники воркспейса + `CMD tsx packages/server/src/index.ts`.
Собирается только web (SPA → `public/`), сервер/shared/core — из исходников.

Если сборка на Render упадёт — прислать логи стадии build/deploy; вероятные точки:
`pnpm --filter @aemr/web build` (нехватка памяти на free — тогда поднять план на время сборки)
или нативный `better-sqlite3` (собирается в build-стадии под alpine, обычно ок).
